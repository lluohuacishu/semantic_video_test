# GLC 蒸馏研究

更新：2026-10-29。专用分支：codex/glc-distillation，基于 codex/glc-streaming-optimization 的 a6fdbd3 分出。

项目仍要求接收端恢复可观看视频，最终面向 Jetson Orin NX Super 16GB。当前先研究 GLC 的局部轻量化，不以实时播放为验收要求。

**最新：[第二轮完整结果](round2/第二轮结果_20261029.md)。** 已盘点本机54段、24,115帧RGB；49个训练文件去重后提供3,052个P帧。1099万参数学生四组各5000步，共训练约47分钟；候选为教师迁移＋纯教师L1，UV96验证25.90 dB（教师28.13），解码核心约加速2.05倍。旧007/025改善，但新场景仍有明显色偏和模糊，暂不能替换。[整包盘点](round2/素材盘点_20261029.md)、[固定协议与复现](round2/复现说明.md)记录全部范围。

## 当前结论

优先验证**最终 RGB 生成器的局部蒸馏**：冻结原压缩、熵编解码和潜变量参考链，离线缓存教师数据，训练小型生成器。第一版可以只处理占多数的 P 帧，I 帧沿用原生成器。

GLC 已公开网络与预训练权重，完整训练脚本未公开。局部蒸馏可以自行建立学生训练流程；它仍需要训练资源。完整编解码器的蒸馏不属于当前已验证范围。

## 本机实际短训与先前预算

首轮在上述RTX4060上训练完整512×288有效画面（填充512×320）、batch1、BF16训练/FP32验证、L1损失：KD组约539秒，GT组约541秒，平均每个更新约0.101秒，本进程峰值allocated约1.55GiB。第二轮1099万参数模型平均约0.130秒/步，每组约707秒，四组47.12分钟，峰值allocated约2.09GiB。它们证明本机能做真实学习，不能保证到时即可获得可用模型。

下面保留的是此前合成计时及长训规划，不能替代真实收敛结果。

设备为 RTX4060 Laptop 8GB，现有 torch 2.5.1+cu124。假设教师已缓存、训练256×256块、batch 2，仅训练约880万参数学生：

- 短测约0.089秒/步；60秒连续负载的中位数约0.092秒，含停顿的平均值约0.218秒。
- 对应本进程 PyTorch 峰值 allocated 约1.5GiB，未包含其他应用和CUDA上下文。
- 损失负载为L1加冻结的未训练VGG16特征计算代理。输入是合成数据，AdamW学习率为0；不是实际LPIPS质量验证或正式学习试验。
- 按30万至50万步加上数据、验证和精修余量，一轮可先预留24-72小时GPU预算。数据与训练流程准备好后，初步试跑、调整和独立视频验收按3-7天安排。

上述步数和余量是规划假设，不能保证训练到时就可用。单帧蒸馏可能继承教师闪动，也可能因平滑而丢失细节；时序稳定性需单独验证。

## 下一轮优先级

1. 先区分全局颜色偏差与纹理丢失。UV108约81.8%的MSE对应整幅通道均值偏差；这只是事后诊断，不是接收端修正或原因证明。
2. 在固定监督下对照归一化分组、迁移/通道缩减及更宽学生；当前迁移最终只高约0.29 dB，不能保证换初始化就修好泛化。保留原图监督对照。
3. 分别验证特征/感知约束对鱼体细节的影响，再处理时序与GOP切换。正式泛化需来源关系明确、未参与调参的素材；007/025继续作为旧回归。像素掩码不是RGB蒸馏训练的必需标签。
4. 将已验证的实验解码策略工程化为生产模型标识与RGB校验协商；原载荷、原潜变量校验继续保留。
5. 最后验证Orin数值兼容和实际收益，不从桌面结果线性换算。

原有011/021是开发片，不作为未经使用的独立测试集。原优化阶段的已完成矩阵继续复用。
