# 开源与论文参考：与当前项目的关系

整理日期：2026-10-17。以下链接来自本次方向调研的官方文档、论文原文、出版页面或作者仓库。没有在本机复现这些新增方案，也没有下载新的模型训练。仓库存在不等于环境、权重及硬件可以直接在当前机器运行。

当前任务允许离线文件传输，20–40 kbps 是发送速率约束；因此不能把论文中的信道符号比、压缩比或实时帧率直接换成已经满足本项目的 kbps。

## 优先借用成熟组件

| 资料 | 主要做法 | 与本项目的关系及边界 |
|---|---|---|
| [FFmpeg addroi](https://ffmpeg.org/ffmpeg-filters.html#addroi) / [libx265 实现](https://www.ffmpeg.org/doxygen/trunk/libx265_8c_source.html) | 用 ROI side data 表达区域量化偏移，编码器内部进行质量分配 | 优先验证一条标准视频流，减少多路编码与贴图恢复；x265 路径要求 AQ。静态过滤器和动态逐帧 ROI 是两回事，本地支持情况尚未实测 |
| [x265 编码预设](https://x265.readthedocs.io/en/stable/presets.html#zero-latency) | 编码效率、计算量、延迟之间的成熟配置 | 允许离线后可以评估 B 帧和前视；先统一比较条件，不能保证某预设在所有视频上都更好 |
| [OpenBSD sftp 手册](https://man.openbsd.org/sftp.1) | 标准文件传输及 `-l` 带宽限制 | 将来需要成熟文件传输时可参考；现有 TCP 可以先保留。工具标称限速不自动等于物理链路包含所有开销的速率 |
| [Microsoft MLVC](https://github.com/microsoft/mlvc) | 已训练神经视频编码模型及码流工具 | 旧项目已经复用，无须重新造底层编码器；当前本地版本和补丁已归档，未升级仓库 |
| [SAM 2](https://github.com/facebookresearch/sam2) | 提示驱动视频分割及传播 | 后续真有时序 ROI 稳定性需求再考虑；它不会自动保证“识别所有鱼”，也不是当前必须引入的组件 |

FFmpeg `addroi` 的过滤器源码：[vf_addroi.c](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavfilter/vf_addroi.c)。动态目标可能需要在每帧设置 `AVFrame` 的 ROI side data，而不是只添加一个固定矩形命令。

## 对当前项目的路线排序

1. 标准视频编码 + 语义 ROI + 受限速文件传输：最符合已确认的目标，优先验证。
2. 现有双区域 `.scv` 原型：保留可运行历史设计、比较证据和兼容回退价值。
3. 改进检测/分割或增加跟踪：在确认发送端漏保护是主要瓶颈后再做。
4. MLVC 训练、DeepSVC/JSCC、生成式重建：作为后续研究分支，满足当前系统目标不以它们为前提。

以上为针对当前约束的工程判断。比较这些工作时，应分别报告可观看性、任务效果、文件/信道预算、计算量和传输时间，不能只摘取某一个“低码率”数字。
