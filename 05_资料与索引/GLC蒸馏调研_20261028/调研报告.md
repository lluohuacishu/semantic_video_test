# GLC 蒸馏可行性调研

日期：2026-10-28。对象：本项目正在使用的 GLC-Video 与真实 .glcv 编解码流程。结论依据为论文、作者仓库和本地静态结构核对；本次没有训练、GPU 推理、模型替换、旧矩阵重跑或系统安装。完整统计见[本地结构核对.json](本地结构核对.json)。

2026-10-29补充：已完成有限的本机前向、反向和优化器计算计时，未进行真实学习；最新硬件结果与训练预算见[耗时预估](../GLC蒸馏耗时预估_20261029/耗时预估.md)。下文保留10月28日的调研口径。

## 结论

**GLC 有蒸馏的可行性，优先考虑最终 RGB 生成器的局部蒸馏。现有证据不足以宣布“蒸馏就是目前最好的方式”，也不能把蒸馏理解为无需训练资源。**

需要分开看三个问题：

| 问题 | 判断 |
|---|---|
| 没有 GLC 官方完整训练脚本，还能蒸馏吗？ | 可以。可运行的教师结构和权重已经具备；可以自行编写学生的监督训练流程，尤其可以避开完整熵模型的端到端训练。 |
| 没有任何训练 GPU，能否靠蒸馏解决？ | 蒸馏仍须更新学生参数。CPU 理论上可以做验证，但不能据此承诺能在合理时间内训练出可部署模型；需要可用的小显存卡、借用或短期外部训练资源之一。 |
| 蒸馏会同时解决轻量化与水草闪动吗？ | 轻量化有结构基础；时序稳定性是额外目标。单帧模仿教师可能继承闪动，也可能因抹掉纹理而看起来更稳定。必须独立评价。 |

研究方向可以确定为“固定压缩与参考链，蒸馏轻量潜变量到图像生成器”，先验证训练资源和质量，再决定是否扩展到编码端或时域学生。

## 官方开放范围与可借鉴证据

GLC 论文说明了自编码器学习、变换编码学习、联合微调三个阶段；这是训练方法说明，不能直接当作可运行训练工程。局部生成器蒸馏不要求重做这三个阶段。[GLC 论文 IV、V-A](https://arxiv.org/html/2505.16177v1)

| 工作 | 对本项目有用的证据 | 不能直接套用的部分 |
|---|---|---|
| [KDIC，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Chen_Knowledge_Distillation_for_Learned_Image_Compression_ICCV_2025_paper.pdf) | 模块化蒸馏已用于学习式图像压缩；说明学生结构和率失真约束都重要。 | 其教师是 S2CFormer，不是 GLC。原实验为 25 万步模块迁移加 75 万步微调，使用 A100，不能视为低算力即插即用配方。 |

| [Neodragon，3.2](https://arxiv.org/html/2511.06055v1) | 在保持原潜变量空间的前提下，更换并训练高效解码器，支持“单独替换输出生成器”的研究思路。 | 其视频解码器实验使用 8 张 80GB H100、20 万步；只能借鉴模块解耦，不能据此推算本项目训练成本。 |

[GVC-RT 作者仓库](https://github.com/semcomm/GVC-RT)当前有推理代码和预训练模型，训练代码仍列为未完成事项。它可以作为方法参考，但不是现成的 GLC 蒸馏训练框架。

本次未核实到作者发布的 GLC 蒸馏学生权重或完整配方。这个判断限于本次检索范围，不代表不存在未发表或未索引的工作。

## 本地代码为什么支持先蒸馏 RGB 生成器

当前实际适配器为 04_外部依赖快照/semantic-video-training/scripts/glc_video_codec.py。它先从真实码流恢复特征，再得到重建潜变量，最后调用 model.vqgan.generator(latent) 输出 RGB。

~~~mermaid
flowchart LR
    A["码流中的 z/y"] --> B["固定的熵解码与概率模型"]
    B --> C["固定的潜变量解码器"]
    C --> D["重建潜变量 latent"]
    B --> Y["ref_y：供后续帧使用"]
    D --> R["ref_latent：供后续帧使用"]
    D --> T["原 RGB 生成器"]
    D --> S["候选轻量 RGB 生成器"]
    T --> O1["教师图像"]
    S --> O2["学生图像"]
~~~

关键点是：**当前下一帧参考使用 ref_latent 和 ref_y，最终 RGB 输出没有反馈到这条参考链。** 因而只替换最后的生成器，可以把学习问题限定为“同一个重建潜变量，生成尽量接近教师和原图的画面”。这属于基于本地代码的推断，尚未进行学生集成验证。

需要分清两个名字：GLC 内部的 video.decoder / image.dec 会产生后续参考；vqgan.generator 才是这里建议先蒸馏的 RGB 网络。直接替换前者会改变参考状态，复杂度明显更高。

既有[算子诊断](../收束证据_20261027/GLC_operator_profile_20261025_recovered_01/GLC算子级诊断报告.md)已把 RGB 生成器定位为主要热点：一个普通 P 帧的带分析器 CUDA Event 区间约为编码端 149 ms、解码端 151 ms。它用于定位，不用于计算可部署加速比，也不能换算成 Orin 性能。本次没有重跑这些实验。

## 新做的结构核对：有缩小空间，但还没有训练结果

只在 CPU 上读取已存在的权重，并在 meta 设备构造网络统计参数，没有执行 forward、backward 或优化器。可用[核对脚本](inspect_structure.py)复查。

| 网络 | 基础通道宽度 | 每级残差块数 | 参数量 | FP32 参数原始字节 |
|---|---:|---:|---:|---:|
| 原生成器，单个 I 或 P 网络 | 128 | 3 | 42,515,587 | 170,062,348 |
| 候选 A | 64 | 2 | 8,800,707 | 35,202,828 |
| 候选 B | 64 | 1 | 6,616,259 | 26,465,036 |

三者保持 256 通道输入、16 倍空间上采样和 RGB 输出。候选 A 参数约为教师的 20.7%，可以作为较保守的首个学生结构。**这只是结构候选，不是已训练出的 880 万参数模型，也不是整个 GLC 参数减少 79.3% 的结果。**

I、P 两个教师生成器结构相同，但本地权重摘要不同，不能假定两者可无条件共享一套学生权重。低预算起点可以先蒸馏占多数帧的 P 生成器，I 帧继续用原教师；之后再研究独立 I 学生或带帧型条件的共享学生。

结构参数更少不会自动给出相同比例的实际加速。其余网络、熵编码、数据搬运以及最终画质要求仍会影响端到端收益。

## 不同蒸馏范围的可行性

| 蒸馏位置 | 对码流与状态的影响 | 当前建议 |
|---|---|---|
| 最终 RGB 生成器 | 保持原重建潜变量时，压缩 z/y 载荷和潜变量参考可以保持；输出 RGB 会变。 | 首选的小范围验证。 |
| 输入 VQGAN 编码器 | 生成的编码特征会变；可以研究保留原解码端，但码率、画质和率失真训练都要重新验证。 | 若 Orin 发送端仍是主要瓶颈，作为后续方向。 |
| 潜变量解码器、上下文、概率网络 | 会进入参考或熵解码路径；近似误差可能使后续概率与参考不一致。 | 不适合作为缺少训练资源时的首轮目标。 |
| 整个 GLC | 需要恢复率失真训练、量化近似、长序列训练和完整收发验证。 | 当前资源条件下不建议直接启动。 |
| 带历史信息的轻量 RGB 生成器 | 可在输出侧学习时序一致性，但增加学生状态、训练开销和重置设计。 | 单帧学生达到可用质量后，再作独立研究。 |

## 适合本项目的低预算方案

建议采用“教师离线生成数据，学生单独训练”的分离流程：

1. 冻结当前 FP32 GLC，使用真实编解码路径得到重建潜变量 latent、教师 RGB、帧型、q 和序列位置；原图只作训练或离线评价目标。
2. 将这些数据缓存到磁盘。训练时不加载完整教师，也不反向穿过 rANS、码本索引和参考解码过程。
3. 从候选 A 开始，只训练学生生成器。第一轮使用像素重建与教师模仿损失；可逐步加入固定感知网络的损失，但先不引入对抗训练。
4. 先证明速度、显存与可接受画质，再决定是否增加时序训练。第一轮不做大规模结构或参数搜索。

输入应是**实际码流恢复出的重建潜变量**。只拿原图经过 VQGAN encoder 的特征，或者随机噪声训练，会偏离最终使用的输入分布。缓存要记录精度、预处理、padding、q、I/P 帧型及教师版本；裁剪还要处理归一化和注意力的边界差异。

一种候选目标为：

~~~text
L = a · L1(学生RGB, 教师RGB)
  + b · L1(学生RGB, 原图)
  + c · 感知损失(学生RGB, 原图)
~~~

这是本项目的建议，尚未验证系数或有效性。仅第一项属于直接输出蒸馏；原图监督可约束教师的失真继承。若要证明蒸馏带来净收益，应补上“相同学生只用原图训练”的对照。

## 训练资源与数据需求

| 可用条件 | 可行性判断 |
|---|---|
| 完全没有可用于训练的 GPU | 可以完成结构设计、CPU 单步检查和数据准备；不能把有用规模的训练当作已经解决。需要落实训练资源，或采用已有模型的部署优化。 |
| 现有 RTX 4060 8GB 允许训练 | 离线缓存教师、只训练小学生是值得做资源探测的方案。可从 128/256 像素输出样本、batch 1 开始；8GB 能否容纳目标损失和反向仍待实测。 |
| 有借用或短期外部 GPU | 可以扩大样本、分辨率与短序列训练，但应在固定小验证可行后再投入。没有给出未经测量的费用或完成时间。 |

冻结教师只省去教师梯度、优化器和部分保存开销；在线教师前向仍需算力。缓存能将这部分工作移出学生训练循环，不能免除教师数据准备时间。感知网络即便冻结，也可能需要保留通向学生输出的梯度，因此仍有计算和激活显存开销。

以一个 256×256 输出样本为例，256×16×16 的 FP32 潜变量占 256 KiB，两份 uint8 RGB 各占 192 KiB，合计约 640 KiB；一万份约 6.1 GiB，未计元数据、文件格式和压缩。这里只是存储核算，不是建议必须训练一万帧。

现有 011、021 是反复看过的开发片，不能同时承担训练和最终泛化验收。应按原始视频或来源组划分训练、验证、测试，避免相邻帧泄漏。小规模试验可以先检查能否学习，但不能凭少量片段证明泛化。

## 与水草闪动的关系

普通单帧蒸馏的目标主要是缩小网络并模仿教师，不会自动建立时间一致性。若教师的水草细节逐帧变化，学生可能照着学；若学生输出更模糊，时序误差也可能下降。

后续可在相邻帧上增加带遮挡掩码的运动补偿约束，比较学生的变化与原视频真实变化，避免把正常运动压平。原图、运动场和掩码可以仅用于训练；部署时是否需要历史输入，取决于学生设计。此扩展是待验证方案，不是 GLC 已证明的能力。

评价必须同时看原速视频、细节损失、鱼边缘拖影和时序指标，不能只看 PSNR 或代理误差。

## 真实码流集成必须保留的界限

“压缩载荷不变”和“当前 .glcv 完整文件逐字节不变”需要分开记录：

- 仅替换最终生成器时，原 z/y、熵模型和潜变量参考可以保持。
- 当前 .glcv 还校验 RGB 重建摘要，头部记录模型与运算信息。学生输出有意不同，旧教师的 RGB 摘要通常不会通过。
- 首轮可在独立实验中先验证原解码与潜变量，再把同一潜变量交给学生输出。应明确标注学生输出，不能声称其 RGB 与教师完全一致。
- 正式集成需要独立的渲染器/学生版本和权重签名，保留传输完整性与潜变量参考校验。若重封装了新 RGB 摘要或元数据，完整文件大小和哈希须重新统计。
- 学生权重预置部署时，不必逐帧发送；部署包大小和每段视频码流仍应分别报告。

跨 RTX / Orin 的原熵解码兼容问题不会因为换成小生成器而自动消失。

## 不应遗漏的无需训练路线

如果最终 Orin 主要承担编码，当前编码端为展示与校验执行的 RGB 生成可能可以移出发送关键路径。潜变量参考仍须保留，RGB 哈希相关容器设计也要调整；这是一个可与蒸馏并列评估的方向，尚未实施，不能直接承诺收益。

另一个静态发现是：I 权重内还有两套各 27,577,344 参数的训练辅助代码预测器，当前适配器 frame 路径没有调用它们。导出只含推理需要的模块，可能减少部署存储和常驻参数内存，但不会消除已定位的生成器计算热点。不要把这种裁减报告为蒸馏加速。

固定形状的推理部署、算子融合与经过验证的数值精度策略，也可以作为无训练基线。此前全 FP16 出现过非有限值，本报告没有把全 FP16 视为现成可用方案。

## 建议的下一步及通过条件

建议立项为“GLC 输出生成器的低资源蒸馏可行性验证”，先落实可用训练资源，再按顺序推进：

1. 资源探测：一个固定学生、固定损失，测 forward/backward 的真实峰值显存和单步时间。
2. 小规模训练：缓存独立训练视频的真实重建潜变量，观察验证集曲线、纹理和鱼边缘，不承诺固定步数必然收敛。
3. 正确性：确认 z/y、ref_latent/ref_y 的保留策略，明确新的 RGB 校验口径。
4. 性能：测编码、解码和文件端到端耗时，分别报告学生参数、部署文件、推理内存和训练显存。
5. 质量：与原 GLC、同结构非蒸馏学生比较；有时序目标时再加相应对照。使用未参与调参的视频，并覆盖 I/P 切换和较长序列。
6. Orin：最后在目标设备上验证实际收益与数值兼容；桌面速度不作线性外推。

**当前最有依据的决定：将局部生成器蒸馏列为优先验证方向；在训练资源和质量验证完成前，不将其视为已经成立的最佳部署方案。**

本目录为调研输出，未改变生产代码、模型权重或已完成结果；随蒸馏专用分支发布，当前进展见[蒸馏入口](../../12_优化阶段_GLC蒸馏/README.md)。
