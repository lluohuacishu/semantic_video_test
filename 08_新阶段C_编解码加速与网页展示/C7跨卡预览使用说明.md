# C7 跨显卡预览补丁

更新：2026-10-21。适用于原 `c5-receiver-20261020` 接收包及其配套发送端。

## 这次解决什么

已量化的 native 首帧中，4060/4070 的参考状态和熵解码摘要一致；640×360 画面只有 16 个像素各一个通道差 ±1。原来的严格 RGB 哈希因此拒绝发布视频。此结果只覆盖首帧，不能推断整段误差。

新增明确选择的 `reference_preview`（跨显卡预览）策略：完整文件、模型、独立解码、完整帧数和**整段有序 latent 摘要**仍必须通过。仅 RGB 摘要不同可以输出预览，并持续显示：

> 参考状态校验通过；RGB 非逐位一致，仅供预览，画面误差未验收。

这类结果是 `reference_verified_preview`，`verified=false`、`reference_verified=true`、`rgb_verified=false`。RGB 和 latent 都相同仍记为 `fully_verified`。不改变网络、权重、熵解码计算和码流格式；`strict` 与 `device_pair_test` 继续拒绝 RGB 差异。该策略要求 v2 码流，只允许 GPU 名称差异，其他算术环境条件沿用设备配对准入要求。

## 同学的 4070 怎么安装

1. 关闭原 C5 发送端、接收端和诊断窗口。
2. 解压 `C7跨卡预览补丁_20261021.zip`，双击 `安装C7跨卡预览补丁.cmd`。
3. 输入**已完成环境安装的旧 C5 包里** `semantic_video_test` 文件夹的完整路径。补丁只更新代码和页面；原环境、权重、连接配置、令牌和任务保留。
4. 出现 `installed` 后，仍用原接收端启动脚本启动。打开接收页 `http://127.0.0.1:8774/`；刷新页面，在“连接信息与高级设置”选择“跨显卡预览（整段 latent 必须一致）”，点击“保存高级设置”。默认策略不会被安装器自动更改。
5. 发送端也必须使用新代码。本机开发目录已更新，关闭并重启原发送端即可；其他电脑上的旧发送包也需要安装此补丁，否则旧发送端会拒绝 `verified=false` 的预览结果。
6. 在发送页重新上传已有的 `received (4).glcv`，发起**新任务**。无需重新编码；旧失败任务不会自动变成功。若使用已保存的同一码流，也可从该素材创建新任务。

接收端的端口若由你们改过，以启动窗口中的实际地址为准。双机发送页连接信息填写 4070 的局域网地址，不能填写发送机自己的 `127.0.0.1`。

## 输出怎么判断

- “码流、RGB 和 latent 校验通过”：逐位核验全部通过。
- “预览已完成：参考状态通过，RGB 非逐位一致，画面误差未验收”：可以播放与下载，但不代表画质或跨卡逐位一致已验收；警示在当前结果和历史记录保留。
- latent 不同、帧数不完整、文件损坏、模型不匹配等仍会失败，不发布为预览。
- 预览差异证据可从结果中的诊断下载项取得。两机完整像素误差需要独立原始帧对照，不能从摘要反推。

## 安装可追溯与回退

安装前核验补丁文件 SHA-256、长度及已知旧版本；未知本地代码修改不会被覆盖。运行中的项目进程会阻止安装。可用旧环境 Python 执行 `c7_apply_preview_patch.py --project <目录> --check` 只检查不安装。

被替换文件及原 `bundle_manifest.json` 保存到 `semantic_video_test/C7_patch_backups/<时间>/`，同目录 `receipt.json` 列出更新前后摘要；原包 manifest 增加补丁链。安装过程异常会回滚。需要手工回退时先关闭服务，根据 receipt 恢复 `files/` 内旧文件、删除 receipt 中 `before=null` 的新增文件，再恢复备份的原 manifest。不能只恢复网页而留下新服务或反过来。
