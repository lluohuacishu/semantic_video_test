# C1：常驻执行器、内存帧与预览流程优化

日期：2026-10-19。**C1 已完成：52 个正式任务、6 个门槛任务和 76 项回归通过。主片科研预览就绪时间降低 30.40%，展示降低 37.23%；C2–C4 未启动。**

## 1. 范围与实现

用户阅读 C0 外部评价后明确授权 C1。基线提交为 `cdc2960`，沿用 `codex/glc-c` 分支。原 GLC 神经计算、Python rANS、容器、权重和四档参数保持不变；原编解码入口与 C0 测量代码保留。新代码集中在本阶段目录，使用既有运行环境，没有训练、安装依赖或实现 C2 候选。

- `c1_runtime.py`：单角色常驻执行器、串行锁、逐任务 DPB 重置、独立接收端校验、科研/展示输出策略和状态事件。
- `c1_io.py`：保持 OpenCV 原像素规则的逐帧内存迭代、有界 FFmpeg 原始帧预览管道。实际 EOF 决定容器帧数，RGB 不整段留在内存。
- `c1_worker.py`：有限任务和串行 JSONL 入口；另保留调用原 C0 循环的参考测量控制。
- `run_c1.py`、`summarize_c1.py`：小样本门槛、交错对照、常驻策略比较、四档兼容与可追溯汇总。

科研模式保存所有源/重建 PNG、逐帧 PSNR、源 RGB/重建 RGB/潜变量摘要、码流、JSON 和 MP4；展示模式保留相同的码流、逐帧指标/摘要及 MP4，不生成 PNG 中间文件。科研模式另测 PNG 无损压缩级别 6→1 的成本变化。PNG 文件大小与 `.glcv` 通信字节数分别报告。

运行说明见 [C1 复现说明](C1复现说明_20261019.md)。

## 2. 比较方法

固定 C0/B4 开发片 SHA-256 `6683af45254bdaed431658e5f7515cddaeb42df2382f18b983e6e1cba7ae436b`；主要档位 `compact` 为 640×360、12.5 fps、125 帧。GLC q0、GOP64、reset32、容器 v2、确定性 FP32。机器仍为 Windows、RTX 4060 Laptop、PyTorch 2.5.1+cu124；保留平衡电源方案，记录每任务 GPU 温度、功耗、频率、显存与运行顺序。

正式性能没有 Profiler 和逐模块 Python 包装。参考与 C1 都计入输入 RGB 哈希；外层墙钟另作复核。科研模式按参考 PNG6 → 内存 RGB/原始帧预览 + PNG6 → PNG1 的顺序，第二轮反转，第三轮再正向运行。展示模式另做三对交错对照。双方最终输出范围一致；展示参考按旧路径制作预览后，在计时内清理自身 PNG 中间文件。

“内存 RGB/原始帧预览”对照是这一组工程改动的整体收益：包含取消 PNG 读回、原始 RGB 预览与接收端复用已加载熵表的校验，不将其解释为某个单独文件操作的精确贡献。PNG 压缩级别对照则只改变 `png_level`。最终组合直接测量，不使用分项节省之和代替。

另以相同的连续三个展示任务，对照一个常驻进程与三个新进程。每种策略只有一组三任务序列；进程启动、首次初始化和退出均计入，不把该结果再次加入“热态对热态”的收益。

`evidence_ready` 包含本模式必需证据与 JSON；`offline_view_ready` 进一步等待所有 MP4 完成。C1 预览与处理重叠，管道等待已进入墙钟。两端时间相加只是分别执行的编码、解码之和，没有测浏览器、通信链路或真实水声端到端时间。

## 3. 性能与逐项归因

以下主结果来自已完成并验证的三组成对实验，所有数值均为秒。“降幅”为每对分别计算后的中位数，不是分别取中位数后再相除；范围为三对最小–最大值，不是置信区间。

### 3.1 最终组合：分别运行的编码与解码时间之和

| 输出范围 / 计时边界 | 同期参考中位数 | C1 中位数 | 配对降幅中位数 | 配对降幅范围 |
| --- | ---: | ---: | ---: | ---: |
| 科研 / 证据就绪 | 102.531 | 71.837 | 29.94% | 29.59–30.05% |
| 科研 / 预览就绪 | 103.650 | 72.144 | 30.40% | 30.06–30.52% |
| 展示 / 证据就绪 | 102.224 | 64.703 | 36.78% | 36.64–36.91% |
| 展示 / 预览就绪 | 103.454 | 65.010 | 37.23% | 37.08–37.35% |
| 科研 / 执行器外层墙钟复核 | 103.655 | 72.151 | 30.39% | 30.06–30.52% |
| 展示 / 执行器外层墙钟复核 | 103.458 | 65.019 | 37.23% | 37.08–37.34% |

科研预览就绪的 C1 三次合计为 **72.033、72.328、72.144 s**；展示为 **64.936、65.010、65.191 s**。完整科研输出也超过本片“总处理时间降低 20%”的工程目标；约 1.44× / 1.59× 的提速尚未达到 2×，也不表示 C 轮网页和跨素材验收完成。

分角色看，科研编码证据就绪中位数从 63.581 降至 42.455 s，解码从 38.964 降至 29.566 s；展示 C1 分别为 37.936、26.803 s。C1 科研帧内处理仍约为编码 36.893 s、解码 26.446 s，已成为主要剩余开销；这不是 CUDA kernel 时间，也不能直接推导 C2 某项优化的收益。

**分母采用本轮交错对照。** 本轮科研参考证据就绪合计约 102.531 s，比历史 C0 的 111.57 s 更快。历史数据的负载、温度、运行顺序和埋点条件不同，不能用历史较慢值扩大 C1 提升，也不把本轮三次小范围波动视为稳定性已经得到充分证明。

### 3.2 逐项归因与负结果

下表使用预览就绪边界，仍为三对差值的中位数。

| 相邻改动 | 角色 | 节省时间 | 配对降幅 | 节省时间范围 |
| --- | --- | ---: | ---: | ---: |
| 原路径 PNG6 → 内存 RGB / 原始帧预览，仍 PNG6 | 编码 | 1.186 s | 1.84% | 0.894–1.238 s |
| 同上 | 解码 | **−0.109 s** | **−0.28%** | −0.110–0.036 s |
| 内存路径 PNG6 → PNG1 | 编码 | 20.610 s | 32.58% | 20.442–20.744 s |
| 同上 | 解码 | 9.820 s | 24.94% | 9.628–9.858 s |

仅换内存路径收益有限，解码中位数略退化。**完整科研模式的主要实测收益是降低 PNG 无损压缩级别**，不能将约 30% 全归功于模型常驻或取消 PNG 读回。展示模式的最终组合还取消了 PNG 落盘，完整输出成本已直接测量。

科研 PNG 的代价也保留：编码端源帧 + 重建帧从 **67,388,634 B** 增至 **77,998,535 B**；接收端重建帧从 **35,131,591 B** 增至 **40,696,292 B**。两端合计由 **97.771 MiB** 增至 **113.196 MiB（+15.78%）**。保存后的 PNG 像素逐帧核对一致；PNG6 内存路径与原路径的 PNG 总大小也一致。展示模式没有 PNG。三种路径的 compact 通信文件均为 **26,397 B**，本地证据增量不进入通信包。

### 3.3 模型常驻与冷态成本单列

同样的三个展示任务，在一个常驻进程与三个新进程中分别执行，包含导入、初始化、任务、每任务 GPU 快照及进程退出；外部 B4/ffprobe 验证对双方同样排除。

| 角色 | 三个独立进程合计 | 一个常驻进程三任务 | 组节省 | 平均每任务节省 |
| --- | ---: | ---: | ---: | ---: |
| 编码 | 130.893 s | 121.258 s | 9.635 s | 3.212 s |
| 解码 | 97.249 s | 85.376 s | 11.872 s | 3.957 s |

每策略只有一组三任务序列，不提供置信区间，也不能把上述节省再加进热态对热态的 30% / 37%。常驻首次任务仍付初始化成本；没有丢弃首次任务或隐藏预热。

科研冷态单次的“进程计时起点至任务返回”参考合计 **114.195 s**，C1 **83.647 s**，分别由独立编码和解码进程组成。每实现每角色只有一次，作为成本示例，不作为三重复性能结论。这里包含预览及状态写入，不能称为精确的证据就绪时刻。冷态指新 Python/CUDA 进程，操作系统文件缓存未清空。

### 3.4 工况与计时修正

原 46 个正式样本的任务前后 GPU 快照范围：37–65°C、7.10–76.31 W、SM 频率 210–2505 MHz、GPU 利用率 1–72%、设备显存已用 3,809–6,239 MiB。它们只是端点快照，不是运行中峰值、连续功耗或 kernel 时间；未锁频。电源方案 GUID 为 `381b4222-f694-41f0-9685-ff5bb260df2e`（平衡），启动时 BatteryStatus=2、电量 98%。原 `powercfg` 的本地化名称存在解码乱码，GUID 保留可查。compact 的 PyTorch peak allocated：编码约 1,638.87 MiB、解码约 1,519.82 MiB。

收尾审阅发现，原冷态 `process_launch_to_evidence/view` 用外层调用起点加内层时长，漏计内层计时前准备。原始 JSON 和当时源码保留；汇总将旧两个端点置为 `null`，只用原 `startup_before_first_task_seconds + outer_call_wall_seconds` 恢复准确的“至任务返回”。最终代码显式记录 `task_timer_origin_perf_counter`，新端点由真实内层起点计算；CPU 回归用人为延迟检查该差异。**主表热态内层时间、外层墙钟和常驻组进程时间不受此元数据修正影响。**

四档补测使用修正后的新目录与源码指纹，原主矩阵没有伪称为最终版本重新测量。另一处修正为 detail_motion 的离线源帧验证路径，从 A2 `long108/source` 改为已核验的 `long108/glc_540_g64/sender/source`；不改变输入视频、模型或编解码算法。

全部 GPU 测量结束后，最后一项边界回归复现了 worker 拒绝重复输出目录时仍会向旧目录追加 `worker_failure.json` 的问题。最终版禁止对既存目录写入该错误元数据，回归核对目录内所有文件名与 SHA-256 均不变。首次测试的 1 项失败日志保留于本机，修复后 21 项 C0/C1 测试全部通过；55 项 B 回归也通过。该修复只影响失败报告路径和目录存在性检查，未改变神经运算；原补测使用修复前版本，最终差异在小型证据与补丁中明确保留，没有重跑并冒充一组新性能数据。

## 4. 正确性与运行记录

8 帧、66 帧新编码→新/旧解码门槛已经通过；66 帧覆盖 I 帧与 reset32 状态边界。完整矩阵已检查输入像素、完整 `.glcv`、逐帧重建与潜变量、保存的科研 PNG、预览尺寸/帧数/帧率和独立解码。

C1 初次 66 帧新解码在第 35 帧被中断，输出无 timing、validation、进程退出码或 Python traceback；系统 Application 日志未给出原因。该半成品保留并排除。使用已经验证的 `encode66/stream.glcv`，另建 `decode66_c1_recovery` 完成验证，没有重编码或覆盖现场。用户报告了界面闪退，但现有证据不能据此确认 GPU、Python 或应用的故障根因。

原正式矩阵已完成 34 个配对/冷态任务和 12 个常驻策略任务。随后 detail 编码在第 11/125 帧中断，监督状态仍显示 running，但复查没有 Python/FFmpeg 进程；未留下退出码或 traceback。保留原 `supervisor.json`、命令及半成品，另写 `interruption_20261019.json` 标记观察事实，并在 `C1_recovery_20261019/` 仅恢复尚未完成的六个四档兼容性任务。两次中断均排除，不归因为已证实的软件/GPU 故障。

正式结果为 **52/52 任务逐帧 RGB/潜变量匹配 B4，26/26 完整编码文件逐字节匹配 B4**；另有 6/6 小样本门槛任务通过，其中 2 次短编码的神经载荷匹配 B4 对应前缀，4 次新/旧解码匹配。所有正式编码源 RGB 匹配，所有正式解码均独立且源媒体读取为零。科研 PNG 逐张核对像素，全部预览由 ffprobe 核对尺寸、帧数和帧率。

## 5. 证据与边界

- 小样本与中断现场：工作区 `02_实验数据/C_编解码加速与网页展示/C1_gates_20261019/`。
- 正式矩阵：同级 `C1_final_20261019/`；大视频、码流和 PNG 留在本机。
- 修正后补测：同级 `C1_recovery_20261019/`；原矩阵与补测各自有 `manifest.json` 和 SHA-256 核对后的 `measurement_code/` 快照。
- C1 只验证本机同一开发片。独立素材、网页操作、跨设备和真实水声链路没有在本阶段补测。
- C0 尚缺 GPU kernel 级别归因；C1 不把 stream span 当 GPU 忙碌时间，也未因此启动 CUDA Graphs、`torch.compile` 或原生 rANS。
- C 轮工程提速不能证明语义 ROI 的等预算净收益。A/B 历史结论与语义增强负结果继续保留。

机器可读数据见 [C1 汇总](c1_summary_20261019.json)，验证、回归日志摘要与中断记录见 [验证证据](c1_validation_evidence_20261019.json)。[测量版至最终版补丁](c1_measurement_to_final_20261019.patch) 明确记录三处文件的计时元数据/验证路径修正及拒绝重复输出时的证据保护修复，采用零上下文格式，供审阅及在独立副本中反向还原测量版；主矩阵和补测源码快照分别保留于本机。C2–C4 按用户后续指示推进。本阶段源码、报告和小型证据按约定检查后提交推送，大资产继续留本机。
