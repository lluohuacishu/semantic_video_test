## 用户指定的提交节奏

2026-10-19 用户要求：建立 C 轮分支、提交当前成果，**以后每跑完一个阶段提交一次**。执行约定如下：

1. 后续 C 轮工作继续使用 `codex/glc-c`；每个阶段完成后及时提交并推送到同名远端分支，不等整轮结束。
2. 提交内容包括该阶段源码、配置、报告、必要的小型证据及状态更新；注明阶段、实际结果与验证范围。
3. 阶段未达目标或按方案停止时，同样保存负结果与原因，不能写成验收通过。
4. 提交前检查差异，执行与本阶段变更相符的验证；提交后核对远端与本地提交一致。
5. 大视频、`.glcv`、逐帧 RGB、权重和环境继续留本地；仓库保留索引，不重复上传这些资产。
6. 建分支和提交文档不代表已经启动实验；C0、C1 已依次获授权并完成。C2–C4 等待后续指示。

本阶段提交包含 C1 执行器、对照与汇总工具、阶段报告、源码版本差异及小型证据；大体积实验产物仍留在本地 C1_final_20261019、C1_recovery_20261019、C1_gates_20261019 目录。约 30% / 37% 是本机同片离线工程收益；独立素材、网页和真实水声端到端尚未验收。
