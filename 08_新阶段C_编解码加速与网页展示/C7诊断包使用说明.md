# C7 短样本诊断包

当前包：`C7_4060_4070诊断包_20261021_r2.zip`。r2 增加离线数值比较，并默认保存每个已完成的短样本帧，避免 4070 在后续帧出现差异时，4060 缺少对应输出。旧诊断包和原 C5 Release 保留。

后续进展（2026-10-21）：已收到 4070 的 r2 结果，并经用户明确授权只运行一次本机 8 帧诊断。首帧两端 latent/熵摘要相同，仅 16 个像素各一个通道相差 1；详见仓库中的 `C7首帧跨GPU差异实测_20261021.md`。本机 8 帧通过不能代替完整双机验收。原已打包 r2 中的说明对应打包时状态，包内容未被覆盖。

这是定位 4060 → 4070 重建差异的小工具，**还不是兼容修复版**。不需要重新安装 Python 或重新下载权重，也不覆盖原 C5 接收包。

后续报告及 `force_decode_glcv.py`、`forced_decode.json` 已静态核对：整段 latent 一致、RGB 不同；该脚本用 Python 熵后端，原失败任务用 native。复用这份长片结果，下面的短诊断仅在需要定位/量化 RGB 差异时运行；两机比较时应选相同后端。

## 4070 电脑上操作

1. 完整解压本诊断包到一个可写文件夹。
2. 先结束 C5 正在执行的任务。若使用常驻模式，请在原网页释放模型，避免两份模型同时占显存。
3. 双击 `启动C7短样本诊断.cmd`。
4. 在提示中填入原接收包内 **semantic_video_test 文件夹**，例如 `D:\C5\C5接收端_20261020\semantic_video_test`。填文件夹，不是启动脚本或日志文件。
5. 工具加载模型后最多处理 8 帧，并保存每个已完成帧的原始 RGB/参考张量。发现第一处差异就停止；窗口最后会显示 report.json 路径。返回码 1 表示失败/发现差异，不要删除结果。
6. 将本诊断包 `results` 下最新的**整个子文件夹**压缩发回，保留 `report.json`、`frames.jsonl` 和 `.npz` 文件；只发最后一行报错不足以定位。

工具只读取 `.glcv`、哈希参考文件和已安装模型。`.npz` 是这次诊断生成的少量输出，用于比较两台机器的数值差异，不是接收端重建所需输入。

如果 8 帧显示 `sample_passed`，只证明这 8 帧通过。先把结果发回，再决定是否使用随包的 64 帧；不要直接重复完整长片。

## 包内样本

样本来自用户提供的 356,604 B 原码流，使用既有发送端逐帧哈希重封装，没有重新编码。

| 样本 | 帧数 | 大小 | 用途 |
|---|---:|---:|---|
| prefix_001.glcv | 1 | 1,517 B | 单独检查首个 I 帧 |
| prefix_008.glcv | 8 | 3,469 B | 默认诊断，含 I/P 帧 |
| prefix_064.glcv | 64 | 18,106 B | 后续需要时检查首个完整 GOP，含参考状态重置 |

参考 JSON 与对应流的 SHA-256、帧序和完整汇总绑定；改动或配错文件会在模型加载前被拒绝。

## 命令行与本机 4060

启动脚本针对已安装的接收端迁移包。开发机可使用原 Python 环境，显式指向权威仓库。以下是 PowerShell 用法，路径按所在机器替换：

```powershell
& '已有环境\Scripts\python.exe' -X utf8 -B '诊断包\c7_decode_probe.py' --project '原包\semantic_video_test' --check
```

`--check` 只验证路径、码流和参考摘要，不导入 torch，不使用 GPU。去掉 `--check` 才会加载模型运行默认 8 帧。

指定其他样本时使用 `--stream '诊断包\samples\prefix_064.glcv'`，自动读取同名 `.reference.json`；工具拒绝超过 64 帧的流。`--backend python` 只用于后续定位熵后端，默认 native 与原失败任务相同。每次输出到新的 results 子目录，不覆盖历史。

默认 `--snapshots all` 保存已处理的每帧输出。`--snapshots first_and_mismatch` 可恢复仅首帧/首个差异帧的旧方式，但可能缺少另一台机器差异位置的原始数据，不建议用于两机数值比较。原始数据会让 results 文件夹明显大于几 KB 的压缩样本，这是诊断输出大小，不是视频压缩率。

## 离线比较两端输出

两端手动运行**同一个样本、同一个熵后端**后，把两个完整的 results 子文件夹放到同一台电脑。双击 `比较C7两端结果.cmd`，按提示选择原 C5 项目和两份结果即可。开发机也可以使用命令行：

```powershell
& '已有环境\Scripts\python.exe' -X utf8 -B '诊断包\c7_compare_results.py' --left '4060结果子文件夹' --right '4070结果子文件夹' --output '新的比较结果.json'
```

这一步只读保存的数组，使用 NumPy，不导入 torch、不加载模型、不使用 GPU。工具检查流身份、帧序、逐帧与汇总摘要、日志一致性、快照 SHA、RGB/参考状态的实际内容摘要、形状与数据类型，再计算：

- 每帧 RGB 的差异像素数、差异 R/G/B 通道数、MAE、MSE、最大误差和 PSNR（峰值 255）。完全相同时 PSNR 写为 `null`，同时明确 `psnr_infinite=true`，避免输出非标准 JSON。
- `ref_latent`、`ref_y` 的逐位是否一致及浮点误差；正负零等字节不同而数值相同的情况分开呈现。
- CDF 索引、离散符号、压缩分段摘要是否一致，以及首个哈希差异帧是否有成对原始数据。

结果中的 PSNR 衡量**两台机器的解码结果差异**，不是相对原视频的画质。工具不设置任意“可接受”阈值，不将小误差标为跨 GPU 验收成功；来源代码指纹缺失或不同会单独列出，不能据此只归因于显卡。

返回码 0 仅表示至少有一帧完成数值比较；1 表示缺少成对原始快照；2 表示输入错误/不一致。只比较两边都有的数据，缺失帧不填零，也不把短流或提前中止当成整段通过。不同码流或 native/Python 混用直接拒绝。

目前的 `forced_decode.json` 仅含整段哈希，不能作为本工具的 results 文件夹，也不能从中计算像素误差。旧版诊断结果若有成对快照仍可比较；缺少的帧会明确列出。

诊断包 SHA 清单见 `package_manifest.json`，原失败流和全部结果是否通过不由清单保证。r2 打包时仅做 CPU 逻辑检查、样本字节校验和 `--check`；后续收到的 4070 结果及获授权的本机短诊断另见首帧实测报告。
