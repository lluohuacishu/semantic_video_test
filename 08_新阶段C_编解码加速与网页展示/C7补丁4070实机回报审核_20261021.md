## 核对与修正

1. 同目录补丁 ZIP 的 SHA-256 与本机交付包完全一致，producer commit 匹配。报告中的码流、latent 和 RGB 缩略摘要均与此前已知完整值相符；缩略值不替代本次原始 JSON 的完整哈希核验。
2. 报告第 3 节将“逐帧缺少发送端哈希”称为 compact 模式，需区分：这是 **v2 容器存储有序聚合摘要的规则**，与网页 compact 画质档位不同。
3. `0309bd6` 的标准整段诊断中，`mismatched_channels` 是顶层字段，RGB 差异应记录为 `["rgb_sha256"]`；逐帧记录用 `sender_checksums_match=null` 表示不能定位逐帧 RGB 一致性。报告中“逐帧 mismatched_channels 为空 / expected_frames 跳过”的具体描述无法在当前标准整段代码中对应，需原诊断 JSON 才能进一步解释。该文字问题不影响报告列出的最终预览判定与补丁设计相符。
4. 整段 latent 一致支持帧间参考状态匹配，但不能据此声称已独立对照全部 CDF 索引与熵符号；此前 native 首帧的四组熵摘要确有单独核验。
5. “16 个像素各差 ±1”只来自此前**首帧**原始数组对照。此次报告没有提供整段像素误差，不能把这个幅度推广到 1239 帧，也未证明具体 GPU 算子根因。
