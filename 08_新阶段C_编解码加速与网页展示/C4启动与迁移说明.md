# C4 启动与迁移说明

## 本机使用

双击本目录 **启动C4演示.cmd**，打开 http://127.0.0.1:8773/。旧“启动C3网页.cmd”兼容转发到同一入口。

1. 上传普通视频，或选择已有演示素材。
2. 手动选择四档之一，点击“准备视频”；此时不启动 GPU。
3. 点击“开始压缩与重建”。运行中可取消；单服务内任务串行。
4. 完成后比较两路画面，下载 .glcv 与重建 MP4。详细计时和历史记录位于折叠区。
5. 页面刷新恢复该标签页的任务；不同标签页独立记忆。关闭整个标签页后可从“最近任务”重新选取。
6. 关闭网页不会停止服务或已启动任务；在启动器控制台按 Ctrl+C 会通知未完成任务取消并等待清理。

默认按四档的帧数/间隔采样，不按任意输入的 10 秒截取。compact 默认 125 帧/间隔 2：25 fps 输入输出 10 秒，29.97 fps 输出约 8.34 秒。只处理视频，无音频；短文件以实际 EOF 为准。

服务仍是本机码流交付，不实际模拟网络或水声。浏览器等待、编解码和理论发送时间分开显示。

## 换电脑或换依赖目录

1. 获取整个代码仓库；不要只复制网页文件。
2. 单独准备兼容的 Python 环境、GLC 上游源码、预共享权重、FFmpeg/FFprobe、native rANS 库。它们不随 Git 分发。本机验证环境为 Python 3.12.14、PyTorch 2.5.1+cu124、RTX 4060 Laptop；原依赖说明仍适用。
3. 将 runtime.example.json 复制为 runtime.local.json，修改路径。该本地文件已加入 .gitignore。
4. 每项路径既可绝对，也可相对于**配置文件所在目录**；不是相对当前终端工作目录。支持环境变量和 ~ 展开。
5. 运行预检，再启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\launch_c4.ps1 -Check
powershell -NoProfile -ExecutionPolicy Bypass -File .\launch_c4.ps1 -Config D:\GLCDemo\settings.json
```

配置字段：

| 字段 | 含义 |
|---|---|
| runtime.python | 真正执行 CUDA 编解码的 Python |
| runtime.repo | GLC 上游代码目录 |
| runtime.weights | GLC 权重目录 |
| runtime.ffmpeg | ffmpeg 可执行文件；旁边应有 ffprobe 以运行离线审核 |
| runtime.native_library | 适配本机的 rANS DLL/共享库；缺少时需手动选择 Python 回退 |
| workspace | 可选历史证据树根目录 |
| data_dir | 本机任务、上传及输出保存目录 |
| history_enabled | 携带完整历史证据时 true；只演示上传功能可设 false |

启动器用配置中的 runtime.python；也可设置 GLC_PYTHON 显式选择，建议该环境变量使用绝对路径。服务可用任意 Python 3.11+ 启动，但实际任务用 runtime.python 指定的环境。未配置时尝试本工作区已有“运行环境”链接；普通独立仓库则使用当前解释器和仓库 runtime 子目录约定。

环境覆盖：GLC_CONFIG 选择配置文件；GLC_PYTHON、GLC_REPO、GLC_WEIGHTS、GLC_FFMPEG、GLC_NATIVE_LIBRARY、GLC_WORKSPACE、GLC_DATA_DIR 覆盖同名路径。路径环境覆盖优先于配置；--config 优先于 GLC_CONFIG；--data-dir 优先于数据目录配置。

预检只检查路径，没有加载 CUDA、检测驱动兼容性或启动推理。没有 native 库时保留 Python 回退；必须已有可用的 CUDA/PyTorch/模型环境才能真正运行。C4 在同一机器验证了不同配置位置与无历史档案模式，**未宣称第二台机器已经验证**。

## 历史回放是可选资产

仅复制代码和运行依赖、history_enabled=false 即可使用上传功能，四档预设来自仓库。历史证据缺失时显示上传入口，不因缺少 C2/B4 视频而启动失败。若需要原四档示例和实验档案，需另行保留相应 workspace 相对布局及清单中的资产；不会自动下载大文件。

已有服务占用端口时启动器复用该页面；**修改配置后应先正常关闭旧服务再启动**，否则旧服务仍使用启动时的配置。也可显式运行：

```powershell
& '<已配置的 Python>' -B .\c3_server.py --config .\runtime.local.json --port 8774 --open
```

同一任务目录有 OS 锁；未确认退出的 worker 会阻止新任务。多服务应避免同时使用同一 GPU；本阶段只验证单服务串行队列。

## 只读复核，不重复编码

在仓库根运行 C/B 回归，native 测试需配置 GLC_RANS_DLL：

```powershell
$env:GLC_RANS_DLL = '<已验证的 glc_rans.dll>'
& '<已配置的 Python>' -B -m unittest discover -s .\08_新阶段C_编解码加速与网页展示 -p 'test_*.py' -v
& '<已配置的 Python>' -B -m unittest discover -s .\07_新阶段B_GLC语义保护与传输 -p 'test_*.py' -v
```

check_c4.py 接受 --acceptance 指向本机 C4_validation_20261020_r1/acceptance.json，--output 必须为新文件。它读取全部结果、重新做 CPU 取帧及 FFprobe/像素摘要检查、核对取消记录和浏览器下载；不会启动神经推理。最后还会对本机服务检查取消任务下载是否为 404，所以服务应运行，且 acceptance 中 base_url 对应实际端口。

大视频、码流、日志、截图和依赖留在本地；Git 保存配置样例、源码、报告和小型审计汇总。未经新授权不重跑已结束矩阵，不自动开始 C5。
