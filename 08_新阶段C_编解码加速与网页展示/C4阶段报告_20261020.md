# C4 验收报告与 C 轮收尾

日期：2026-10-20。**C4 按用户指定范围完成，C 轮收尾；C5 尚未启动。**

本阶段解决三项可信度验证：完整主片网页闭环、真实 GPU 推理取消与队列恢复、独立来源普通视频上传。同时将首页改为功能演示，并把运行依赖移到可配置路径。没有训练、重跑 C2 矩阵或新增语义增强实验。

## 2. 完整视频、内容与状态校验

主片确实完成了 10 秒/125 帧，而非 C3 的 8 帧门槛：

1. 编码与独立解码逐帧 RGB、潜变量摘要全部一致；接收端 source_media_reads 为空。
2. 完整主片码流与冻结 C2 compact 参考逐字节相同，SHA-256 为 9676a03220ec2d28aef09fde70413ea9a08ea38cc9461509931767789036b7fd。
3. 离线审核重新读取全部源帧，按记录的采样索引独立计算处理后源 RGB 摘要；三项成功任务全部匹配。
4. FFprobe 确认源预览、发送端重建预览、接收端重建预览的帧数、尺寸、fps 和时长。FFmpeg 对发送端/接收端重建 MP4 解码后的像素摘要相同。
5. 主片与新视频两路浏览器播放均到末尾；实际浏览器下载的两份 .glcv 与服务器码流 SHA 相同。另下载新视频重建 MP4，SHA 与服务器预览相同。
6. 事件记录覆盖 prepared/staged → queued → running encode → running decode → verify → done；上传新视频还覆盖 uploading。底层继承 JobStore 的初始化状态名为 uploading，选已登记素材时随即进入 staged，并不发生实际上传。
7. 每个完整任务的两个工作进程均退出 0；取消任务为取消终态而非成功；未完成码流下载返回 HTTP 404。

## 3. 真正的 GPU 取消与恢复

| 情况 | 编码中取消 | 独立解码中取消 |
|---|---:|---:|
| 取消前采样确认进度 | 29/125 帧 | 5/125 帧 |
| 同时采集的整卡 GPU 利用率 | 91% | 88% |
| 工作进程最后完成进度 | 67/125 帧 | 95/125 帧 |
| 服务收到取消至终态 | **1.041 s** | **0.785 s** |
| worker 退出码 | 2 / TaskCancelled | 2 / TaskCancelled |
| 强制终止 | 否 | 否 |
| 后续排队任务 | 新视频 125 帧成功 | 主片 8 帧成功 |

取消前的进度采样与实际点击之间存在浏览器操作延迟，不把 29/5 帧写成精确点击帧；退出时均仍少于 125 帧。设备配置为 cuda，心跳、进程身份、监督器、异常类型和 GPU 快照共同保留，整卡利用率不是进程独占利用率。

两次均在当前帧/预览边界协作退出；launcher 与实际 Python worker 的身份复核均已不存活。后继任务早已 queued，且在前驱 finished_at 之后才 started_at；没有重启服务、手工清队列或删除失败目录。8 帧恢复流逐字节匹配 C2 原参考，未出现跨任务状态残留。

本阶段证明这两次真实路径可取消、释放与恢复，不等价于高频取消、崩溃恢复或长期稳定性保证。

## 5. 功能展示与配置

首页只保留选视频、手动画质、准备/运行/取消、输入与重建、三项关键数字和下载。高级参数、任务记录及详细计时默认折叠。历史 A/B/C 对照、负结果与归因移到“实验档案”，不再占据主展示页。

实际验收中发现多标签页轮询反复写同一 localStorage 键，导致刷新恢复到其他标签页的任务。已改为 sessionStorage 按标签页保存，并在两个标签页选不同任务后复测刷新，恢复正确任务。原错误观察保存在 refresh_bug_before_fix.json。

新增 runtime.example.json、c4_config.py、launch_c4.ps1 和“启动C4演示.cmd”。Python、GLC 上游、权重、FFmpeg、native 库、历史资料根及任务目录均可配置；支持配置文件相对路径和环境变量覆盖。当前本机 runtime.local.json 使用相对目录链接且被 Git 忽略。旧 C3 启动入口转到新启动器。

迁移冒烟在独立配置目录、相对依赖路径和不具备原历史目录的工作区执行：CLI --check、Windows 启动器的配置加环境覆盖、无历史资料的 HTTP 首页/四档/上传入口均通过，零 GPU、零任务。也覆盖浅层仓库路径，不再依赖固定父目录层数。最终审阅修复了模块导入过早加载配置会破坏 --config 覆盖 GLC_CONFIG 的问题，并新增命令行优先级回归。

**没有在第二台电脑实跑。** 配置可迁移不等于安装包、驱动/依赖自动安装或跨 GPU 确定性承诺。详见 [启动与迁移说明](C4启动与迁移说明.md)。

## 7. C 轮结论

C0 基线、C1 流程优化、C2 native 加速、C3 网页整合和 C4 指定验收均已结束。C2 同期最终组合 102.517 → 51.489 s、49.78%、1.991× 的结论保持，**严格 2× 未达到**。新网页仍是每端新进程的冷启动，本次主片浏览器约 60.7 秒不代表实时。

语义 ROI 的等预算净收益、真实水声链路、跨设备复现与长期服务稳定性仍未证明。后续是否增加 C5 由用户决定，不自动开展新实验或继续堆叠页面。
