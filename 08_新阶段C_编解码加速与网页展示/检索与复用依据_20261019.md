# C 轮检索与复用依据

检索日期：2026-10-19（Asia/Shanghai）。目的：寻找能够降低本项目编解码耗时、复用现有网页能力的方法。仅使用论文作者、官方仓库与官方文档作为技术依据。以下区分公开事实和本项目判断，未下载新模型或运行任何候选。

## 1. GLC 本身与相近成果

**GLC-Video。** [作者仓库](https://github.com/jzyustc/GLC)和[视频扩展论文](https://arxiv.org/abs/2505.16177)提供模型路线与预训练入口；仓库安装示例采用 PyTorch 2.5.1/CUDA 12.4，与本机已有环境接近。公开方案基于生成式潜空间和时空先验。此次检查的官方入口中，未找到能直接替换本项目 `.glcv` 编解码器的现成加速包；不能据此断言所有外部分支都不存在。

本项目判断：继续使用已验证的网络与权重。本地 `glc_video_codec.py` 明确说明公开上游测试是估计码量，本项目另加真实熵编码和容器。因此，上游前向速度、估计码量和本地完整文件链路不能直接混用。

**DCVC-RT，CVPR 2025。** [论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Jia_Towards_Practical_Real-Time_Neural_Video_Compression_CVPR_2025_paper.pdf)强调内存 I/O 和调用开销；[官方实现](https://github.com/microsoft/DCVC/blob/main/DCVC-family/DCVC-RT/README.md)提供权重、C++ 熵编码和定制 CUDA 扩展。论文报告其特定条件下 1080p 编码/解码约 125.2/112.8 fps。

本项目判断：参考其“先处理实际运行开销”的原则。数字属于作者模型、硬件与测量协议，不预测 RTX 4060 Laptop 上 GLC 的表现；替换整套模型会重开路线选择，本轮不做。

**DCVC-UF，CVPR 2026。** [作者论文](https://arxiv.org/abs/2606.04410)与[官方代码](https://github.com/microsoft/DCVC)采用多帧块的联合潜变量、并行重建和减少熵码流交互的设计。

本项目判断：证明减少串行交互是一条现有研究路线，但依赖结构变化和相应权重，不是给现有 GLC 加一个开关。仅列为未来参考，不能将相邻 P 帧直接当成可独立并行的任务。

## 2. 可直接复用或薄适配的方法

**Amdahl 定律。** [1967 年原始论文](https://doi.org/10.1145/1465482.1465560)阐述局部加速受未改善部分限制的思想。本轮采用常见的时间占比形式 `1 / ((1-p) + p/s)` 估计候选收益上限，用实测热点占比决定是否值得接入；不把理论上限当作达标预测。

**PyTorch Profiler 与 CUDA events。** [Profiler 文档](https://docs.pytorch.org/tutorials/recipes/recipes/profiler_recipe.html)提供 CPU/CUDA 活动、阶段标记及跟踪导出；[2.5.1 CUDA 文档源码](https://github.com/pytorch/pytorch/blob/v2.5.1/docs/source/notes/cuda.rst)说明异步执行、同步、事件及图捕获。Context7 同时查询了版本化库 `/pytorch/pytorch/v2.5.1`；检索返回的部分示例指向 main，不能直接当成 2.5.1 API 保证。

采用：执行阶段以本机版本为准，正式计时关闭重型跟踪；短段跟踪找热点，墙钟反映用户实际等待。CPU 与 GPU 事件不能不加区分地求和。

**原生 byte-rANS。** [ryg_rans](https://github.com/rygorous/ryg_rans)及其 [rans_byte.h](https://github.com/rygorous/ryg_rans/blob/master/rans_byte.h)公开了 byte-aligned rANS，仓库声明为 public domain。当前 `glc_entropy.py` 已注明其递推来源。

采用条件：复用同源原生核心、保留本地包头与 escape 规则，测试逐字节兼容。64 位/交错/SIMD 变种会涉及不同输出布局，不能因为同属 rANS 就声称兼容。保留项目已有输入边界与损坏码流检查。

**CompressAI rANS。** [官方接口](https://interdigitalinc.github.io/CompressAI/ans.html)已提供 C++ rANS 绑定。

取舍：可作为成熟实现的参考，但其 CDF、绕过符号与流组织须和本地格式核对，不能直接替换 `python-byte-rans-gaussian128-v1`。本轮优先同源 byte-rANS 的最小适配，避免无必要的格式迁移。

**FFmpeg rawvideo 与 pipe。** [rawvideo 文档](https://ffmpeg.org/ffmpeg-formats.html#rawvideo)要求显式说明尺寸、像素格式和帧率；[pipe 文档](https://ffmpeg.org/ffmpeg-protocols.html#pipe)提供标准输入/输出管道。Context7 也核对了 `/websites/ffmpeg_documentation`。

采用：对当前 OpenCV 路径产生的 RGB 做内存传递，接 FFmpeg 制作观看视频。管道没有原始时间戳语义，需明确本项目名义恒定帧率；MP4 写可寻址的普通文件。先验证像素与源帧映射，避免用不同缩放器改变试验条件。`+faststart` 便于已完成文件播放，不等于新建立了神经码流的实时流式播放。

## 3. GPU 加速的适用限制

**CUDA Graphs。** [2.5.1 文档](https://github.com/pytorch/pytorch/blob/v2.5.1/docs/source/notes/cuda.rst)要求固定形状、稳定内存引用和可捕获控制流；同步 CPU/GPU 的操作不适合捕获，CPU 代码不会随 GPU 图自动重放。

取舍：只考虑静态纯 GPU 子模块。当前 `frame()` 有 I/P 分支、CPU 熵编码、NumPy 转换与哈希，不能整体包装后假定每次都会正确执行。图构建、预热和额外显存均计入初始化记录。

**torch.compile / Windows。** [PyTorch Windows 教程](https://docs.pytorch.org/tutorials/unstable/inductor_windows.html)主要讲 CPU/XPU；[Triton Windows 当前维护仓库](https://github.com/triton-lang/triton-windows)另列 NVIDIA 支持和 PyTorch/Triton 版本对应关系，其中 PyTorch 2.5 对应 Triton 3.1。

取舍：不能引用旧 issue 笼统宣称 Windows 完全不支持；也不能把版本表当作本机安装成功或 GLC 兼容的证据。候选须在隔离环境验证，不自动改动已有 `.venv-glc`。图断裂、编译时间和数值变化可能抵消收益。

**TensorRT / FP16 / TF32。** [NVIDIA 精度说明](https://docs.nvidia.com/deeplearning/tensorrt/10.x.x/inference-library/accuracy-considerations.html)说明低精度的动态范围与误差问题；[开发者指南](https://docs.nvidia.com/deeplearning/tensorrt/archives/tensorrt-1020/pdf/TensorRT-Developer-Guide.pdf)也讨论后端运算顺序造成的结果差异。

取舍：本地先验决定熵解码，参考状态又递归影响下一帧；微小数值变化不能仅凭 PSNR 相近就认定兼容。本轮主线保持 FP32 与严格摘要验证；混合精度、量化、蒸馏和重训练不作为默认工作。

## 4. 网页组件与已有项目能力

**Gradio。** [Video 组件](https://www.gradio.app/docs/gradio/video)与[任务队列](https://www.gradio.app/guides/queuing)可用于快速搭建模型演示。

取舍：本项目已经有相同基础能力，改用 Gradio 会产生参数、历史结果和播放交互的迁移工作。作为备选保留，默认扩展既有页面。

**浏览器原生视频。** [MDN requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)提供呈现帧的 `mediaTime` 等数据。

采用：辅助播放时间对齐及漂移诊断；不把多 video 标签称为严格帧同步。已有合成比较 MP4 可直接展示，RGB 静帧负责精确核对。浏览器播放的 MP4 与 `.glcv` 传输文件在界面上分开标明。

**现有控制台。** 本地 `glc_demo_server.py`、`glc_console/app.js`、`docs/GLC网页界面.md` 已包含队列、上传、取消、历史、下载、媒体 Range 与同步播放。`tests/test_glc_demo_server.py` 可为后续变更提供回归入口。此次仅静态阅读，未启动旧服务。

必须补齐：B4 四档与容器 v2 参数链、现有目录整理后的运行环境定位、当前结果索引、统一耗时字段，以及回放/新运行的清晰区分。旧页面配置不能直接当作当前标准。
