# 视频逐帧分割记录

## 目的

把已经训练好的 SUIM 八类图片分割模型用于连续视频，先验证三个问题：视频能否正常读取和保存、单机处理速度能否跟上输入、逐帧预测是否有明显跳变。这个阶段没有加入网络协议、信道损耗或语义码流。

## 运行

在项目根目录执行：

```bat
python scripts\segment_video.py ^
  --checkpoint runs\suim_transfer_20260911\segmentation_best.pt ^
  --input "path/to/test5_5fps_reconstructed.avi" ^
  --output-dir runs\video_segment_test5_5fps ^
  --device cuda --save-masks
```

`--save-masks` 会保存单通道类别编号图。输出目录必须为空，避免不同参数的结果混在一起。默认使用 `mp4v` 写 MP4；如果本机编码器不可用，可加 `--codec MJPG` 改写 AVI。视频的宽高和 FPS 从输入文件读取并原样写入，`--max-frames N` 可先只处理前 N 帧排查问题。

画面出现颜色跳变时，可以加 `--temporal-window 3` 或 `--temporal-window 5`。脚本对最近几帧的类别图做带近期权重的因果投票，最多引入一到两帧的显示滞后。默认值 1 表示关闭，适合先测原始模型速度。

## 本机结果

测试文件为导师资料中的 `test5_5fps_reconstructed.avi`，视频属性为 1280×720、5 FPS、50 帧。使用 RTX 4060 Laptop、CUDA 和输入尺寸 256 逐帧处理：

- 全部 50 帧成功读取和写出，彩色类别视频与叠加视频均可重新打开，分辨率为 1280×720，FPS 为 5；
- 从读帧到生成结果的端到端耗时约 3.16 秒，处理速度约 15.84 FPS，约为输入速度的 3.17 倍；
- 模型前向耗时中位数约 5.22 ms，P95 约 9.83 ms；端到端单帧耗时中位数约 51.61 ms，P95 约 67.30 ms；
- 相邻输出类别图的变化像素比例均值约 18.9%，P95 约 39.6%。这项数值只反映逐帧结果的变化，视频没有逐帧真值，不能当作准确率或时序稳定性指标。

上面的数字来自 `--temporal-window 1`。稳定器不是时序神经网络；是否值得开启，应同时看 `summary.json` 中的 `raw_mean_changed_fraction` 和 `mean_changed_fraction`，并确认处理 FPS 仍高于输入 FPS。

同一视频改用优化后的三帧多数投票后，端到端处理速度约 15.00 FPS，相邻输出变化均值降到 12.1%，P95 降到 31.6%。在 5 FPS 输入下仍有余量；如果输入提高到 15 FPS 以上，应先关闭 PNG 掩码保存并重新实测端到端延迟。

结果目录：

```text
runs/video_segment_test5_5fps_20260911/
  segmentation_color.mp4       彩色类别视频
  segmentation_overlay.mp4     原图与类别颜色叠加视频
  masks/frame_*.png             0～7 类别编号图
  frame_metrics.csv             每帧分阶段耗时和变化比例
  summary.json                  输入、速度、类别占比和统计口径
```

## 如何解读

处理 FPS 高于输入 FPS，表示在当前电脑和当前文件上，离线处理可以跟上 5 FPS 输入；它没有测量摄像头缓冲、网络排队、编码器缓存和接收端显示延迟。当前程序仍是每帧独立推理，颜色跳变可能来自模型误分割。后续若要做语义感知传输，可以先利用 `masks` 区分前景和背景，再分别设置压缩质量；这仍属于语义感知压缩原型，距离神经语义通信还差可量化的语义码流和端到端训练。
