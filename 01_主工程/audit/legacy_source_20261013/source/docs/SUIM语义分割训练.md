# SUIM 语义分割首次训练

日期：2026-09-11。项目：semantic-video-training。

本次完成了八类水下图片语义分割训练、独立测试和单张图片预测。这次模型实际使用像素标签监督，与前一次只还原图片的自编码器是两个独立实验。

先说明结果：模型已经能够区分部分水下区域，但识别效果还不稳定。测试 mIoU 为 37.20%，水生植物类 IoU 只有 0.18%，不能称为可靠的八类分割系统。本次结果用于建立可复核的起始基线。

## 模型在学什么

输入是 RGB 图片，标签是同尺寸的单通道类别图。每个标签像素用 0～7 表示一个类别，模型输出八张类别分数图，在每个位置取最高分的类别。

~~~text
水下图片 → 编码器提取特征 → 上采样并融合浅层特征 → 每个像素的八类分数
                                              ↓
                                     与人工标签比较并更新权重
~~~

使用的 TinyUNet 是按 [U-Net 的编码器、解码器和跳跃连接结构](https://lmb.informatik.uni-freiburg.de/people/ronneber/u-net/)写的缩小版本，并非原论文或 SUIM-Net 的复现。模型有 488,120 个参数，基础通道数为 16，使用 GroupNorm 和双线性上采样。

网络中的“解码器”负责把特征恢复到像素标签的分辨率，不是在解码通信码流。本次没有沿用自编码器的权重，也没有下载预训练模型，所有权重从随机初始化开始学习。

## 数据和预处理

继续使用原先固定的数据清单：训练 1187 张、验证 297 张、测试 110 张，没有重新划分。清单指纹与自编码器实验一致。之前发现的 37 对尺寸异常样本和 4 张测试重叠图片仍排除在训练、验证之外，原文件保留。

- 原图按长边等比缩放到 256，居中补边到 256×256，保留完整视野。
- 标签按完全相同的几何位置变换，缩放采用最近邻插值。
- 补边标签为 255，在训练损失和指标中忽略。
- 训练时图片与标签同步水平翻转，并仅对图片轻微调整亮度、饱和度。
- 验证和测试使用固定变换，不使用随机增强。

这种预处理与前一次自编码器的中心裁剪不同，因此两个实验的图像范围不能混为一谈。索引标签来自原 RGB 标签的八色映射，部分边界存在颜色噪声；尺寸对齐也不等于逐像素标注完全正确。

本数据划分只保证没有精确重复图片跨集合，不保证采集场景独立。原始数据说明和问题清单见 README.md 及 data/SUIM/preparation_report.json。

交叉熵让模型提高正确类别的分数，Dice 项鼓励预测区域与真值重叠。类别权重用于缓解大类压过小类的问题，但不保证稀少类别能学好。实现参数保存在 config.json，交叉熵的目标类别与忽略标签用法可查 [PyTorch 文档](https://docs.pytorch.org/docs/2.12/generated/torch.nn.CrossEntropyLoss.html)。

训练循环耗时 376.456 秒，包含数据缓存和图表写出的脚本总耗时约 383 秒，即约 6 分 23 秒，不含 Python/框架启动。PyTorch 峰值已分配张量显存为 790.1MiB、峰值预留显存为 916.0MiB，均不等于包含驱动、上下文等开销的整机显存占用。8GB 显卡足以完成本次小模型训练。

## 怎样评价分割

IoU = 预测区域与真值的交集 / 两者的并集。

例如预测区域有 100 个像素、真值有 80 个像素，重叠 60 个像素，则 IoU = 60 / (100 + 80 - 60) = 50%。

本项目先累计所有图片的混淆矩阵，再计算每类 IoU，最后等权平均得到 mIoU，包含背景。并集为空的类别不参与平均；假阳性会使原本缺失类别的并集非空，并影响分数。补边 255 全部忽略。逐图 mIoU 的平均不是这个全局指标。

像素准确率是所有有效像素中预测正确的比例，大面积背景容易抬高它，所以选模型使用验证 mIoU。

## 测试结果

第 37 轮的最佳验证 mIoU 为 39.18%。选择轮次后固定权重，在官方 110 张测试图上做 float32 推理，得到：

| 类别 | 颜色 | 测试 IoU |
| --- | --- | ---: |
| 背景水体 BW | 黑 | 82.10% |
| 潜水员 HD | 蓝 | 31.27% |
| 水生植物 PF | 绿 | 0.18% |
| 沉船与遗迹 WR | 青 | 26.87% |
| 机器人与仪器 RO | 红 | 21.30% |
| 珊瑚礁与无脊椎动物 RI | 品红 | 47.77% |
| 鱼与脊椎动物 FV | 黄 | 34.80% |
| 海床与岩石 SR | 白 | 53.31% |
| **八类平均 mIoU** | | **37.20%** |

测试像素准确率为 70.79%。作为检查，全部预测为背景时 mIoU 仅为 4.97%，像素准确率也能有 39.77%，这说明不能只看像素准确率。

这些指标是在长边缩放到 256 后的有效区域计算，不能视为原始高清分辨率的结果，也不是官方论文的复现实验。本轮没有利用测试结果重新选择模型或修改参数。

## 预测图说明了什么

evaluation_test/comparison.png 固定从测试名单中等间隔抽取六张，四列依次为输入、真值标签、模型预测、预测叠加图。灰色区域是补边，不计分。样本没有按预测好坏挑选。

可以看到模型能分出部分水体边界、珊瑚区域、海床和目标轮廓；但存在明显错误，例如把潜水员识别成鱼，鱼体内出现多个错误类别，以及把水生植物误判为珊瑚礁或其他背景结构。小目标和细边界也容易漏掉。

水生植物在验证集上的 IoU 同样只有约 0.16%，说明问题在选模型阶段已经存在，并非只发生在测试集。现有结果不能确定是哪一个因素导致，应优先检查训练样本覆盖、类别采样、标注歧义和模型表达能力，而不能简单归因于显存不足。

先看 comparison.png 和 per_class.csv，再看 learning_curve.png。类别编号 PNG 像素是 0～7，加上补边的 255，直接查看通常近乎黑色；彩色效果应查看 color_predictions 或 overlays。

双击 run_segmentation_train.cmd 可以重新训练，每次默认创建新目录。模型权重用于推理，当前没有断点续训，再次训练会从头开始。

使用自己的图片：

~~~bat
python scripts\predict_segmentation.py --checkpoint runs\suim_segmentation_20260911\segmentation_best.pt --input "path/to/underwater.jpg" --device cuda
~~~

脚本保存原图、类别编号、彩色类别图、叠加图和预测类别占比。先在低分辨率上推理，去补边后把类别分数上采样回原图尺寸，再取类别；输出尺寸与原图相同，不代表原生高清推理。新图片没有真值，所以不会报告准确率。

## 检查与当前边界

已通过 7 项回归测试，覆盖标签和图片几何对齐、异常标签拒绝、已知答案的 IoU、假阳性类别、忽略补边的损失、反向传播以及预测还原尺寸。实际保存的 110 对预测/真值 PNG 也重新累计了混淆矩阵，结果与 JSON/CSV 一致。训练入口和单图预测命令均实际运行过。

现在已经实现的是有监督的图片语义分割模块。没有接入连续视频，没有测视频处理延迟、帧间抖动或传输效果，也没有实现语义码流、码率控制和重要区域压缩。

如果向导师汇报，可以这样说：

> 我们已用 SUIM 的像素标签，在 8GB 显卡上从头训练并测试了轻量八类语义分割模型，建立了数据检查、训练、独立评价和预测可视化流程。它对应研究报告中的视频帧语义分割前置模块。当前 mIoU 为 37.20%，植物、小目标和部分类别混淆仍明显，下一步先改善这些问题，再评估逐帧视频分割以及语义掩码指导压缩的效果。
