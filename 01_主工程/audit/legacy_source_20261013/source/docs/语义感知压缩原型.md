# 语义感知压缩原型

## 作用

分割模型先判断每帧中的类别，再把指定的重要类别区域原样保留，背景按比例降采样后恢复到原尺寸，最后用同一个 OpenCV 编码器写出视频。脚本同时写普通压缩基线，用于观察重要区域保护是否改变文件大小和画面质量。

这个实验没有训练新的压缩网络，也没有把掩码、特征或量化码流通过通信链路发送。它适合说明“先提取语义，再按重要程度分配画质”的思路，不能直接称为神经语义通信。

## 命令

```bat
python scripts\semantic_compress_video.py ^
  --checkpoint runs\suim_transfer_20260911\segmentation_best.pt ^
  --input "path/to/test5_5fps_reconstructed.avi" ^
  --output-dir runs\semantic_compress_test5 ^
  --device cuda --temporal-window 3 --background-scale 0.5 --mask-dilate 2
```

主要参数：

- `--important-classes 1,4,6`：只保护潜水员、机器人、鱼类；默认保护所有非背景类别；
- `--background-scale 0.25/0.5/1.0`：背景缩放比例，越小背景细节越少；1.0 等于不降采样；
- `--mask-dilate 2`：向重要区域外扩像素，避免目标边缘被背景处理覆盖；
- `--temporal-window 1/3/5`：对类别掩码做因果投票，降低帧间跳变；
- `--codec MJPG`：在编码器可用时输出 AVI，默认 `mp4v` 输出 MP4。

输出目录必须为空。`baseline.*` 和 `semantic.*` 使用相同输入、分辨率、FPS 和编码器。`summary.json` 还会重新读取两个输出，统计文件大小、包含封装的平均码率、整体 PSNR/SSIM，以及按预测掩码划分的前景和背景 PSNR。

## 720p 本机试验

输入为 1280×720、5 FPS、50 帧的导师资料视频，设置 `temporal-window=3`、`background-scale=0.5`、`mask-dilate=2`，使用 RTX 4060 Laptop：

| 项目 | 普通基线 | 语义感知 |
| --- | ---: | ---: |
| 文件大小 | 1,134,599 B | 1,133,647 B |
| 平均码率（含封装） | 907.68 kbps | 906.92 kbps |
| 整体 PSNR | 37.31 dB | 37.34 dB |
| 重要区域 PSNR | 36.61 dB | 36.61 dB |
| 背景 PSNR | 38.61 dB | 38.75 dB |
| 整体 SSIM（每 5 帧采样） | 0.8906 | 0.8916 |

在这个短视频和 `mp4v` 设置下，文件大小只减少约 0.08%。这不是程序失效，而是 OpenCV 的 `mp4v` 缺少稳定的目标码率控制，且输入背景本身已经容易编码。把背景比例降到 0.25 后，本次文件大小减少约 0.39%，同时背景 PSNR 会下降。要证明明显的码率收益，下一步应使用固定码率 H.264/HEVC，或把重要区域、背景低分辨率图和掩码组织成分层码流。

## 结果边界

分割错误会直接影响重要区域判断；当前模型在植物、小目标和复杂边界上仍会误分。前景和背景指标使用的是模型预测掩码，没有人工逐帧真值。文件大小、PSNR、SSIM 只描述像素层面的压缩效果，不能代替潜水员/鱼类等语义任务指标。
