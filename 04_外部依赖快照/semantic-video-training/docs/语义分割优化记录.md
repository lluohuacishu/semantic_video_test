# 语义分割优化记录

小目标、高分辨率和多尺度特征的后续消融已单独记录在 [小目标分割消融](小目标分割消融.md)，这里保留原来的迁移学习基线结果。

日期：2026-09-11。项目：semantic-video-training。

本次针对第一版识别弱、植物几乎全漏检的问题，加入预训练特征微调、类别平衡采样和较强数据增强。旧模型、原始数据和划分全部保留，结果用同一批图片、同一份真值和同一评价方式比较。

## 结果

在同一组 110 张测试图上，mIoU 从 **37.20% 提升到 62.65%**，增加 **25.45 个百分点**；像素准确率从 70.79% 提升到 82.73%。各类 IoU 均有提升。

| 类别 | 旧模型 IoU | 优化后 IoU |
| --- | ---: | ---: |
| 背景水体 | 82.10% | 87.47% |
| 潜水员 | 31.27% | 69.23% |
| 水生植物 | 0.18% | 22.96% |
| 沉船与遗迹 | 26.87% | 64.20% |
| 机器人与仪器 | 21.30% | 67.88% |
| 珊瑚礁与无脊椎动物 | 47.77% | 61.53% |
| 鱼与脊椎动物 | 34.80% | 64.26% |
| 海床与岩石 | 53.31% | 63.69% |
| **八类平均 mIoU** | **37.20%** | **62.65%** |

对照图见 runs/suim_transfer_20260911/comparison_with_baseline/before_after.png，依次为输入、真值、旧模型、新模型、新模型叠加图。这六张图从固定测试名单中等间隔选择，与原报告相同，没有按效果挑选。

对照图中，旧模型把潜水员大片识别成鱼的例子得到纠正，鱼体内部的错误类别碎片和海床上的大片误判明显减少。不过植物仍只找出一部分，细边界、小目标和部分背景结构还有错误。62.65% 的 mIoU 是明显进步，不能理解为分割已经可靠无误。

## 第一版的问题与这次改动

第一版 TinyUNet 只有 488,120 个参数，从随机初始化学习。水生植物的验证 IoU 约为 0.16%，说明问题在验证阶段已经存在。数据检查确认植物标签存在，颜色转类别、最近邻缩放、图片/标签同步变换和补边忽略的检查均通过，不能把低分简单归因于标签没有读进来。

本次不是只增加训练轮数，而是做了以下组合改动：

| 改动 | 具体做法 |
| --- | --- |
| 使用预训练特征 | 换为 LR-ASPP + MobileNetV3，3,219,328 个参数，保留官方预训练的特征提取和共享分割层 |
| 重新学习水下类别 | 两个原分类输出层重新初始化为 SUIM 的八类，原始 21 类不直接映射为水下类别 |
| 分开设置学习率 | 特征提取层 0.0001，分类侧 0.001，再按共同余弦比例降低 |
| 增加较少类别的接触机会 | 一半均匀采样，一半按训练图中的类别出现次数平衡，有放回采样，每轮 1187 张 |
| 增强几何变化 | 图片与标签同步水平翻转、±8° 旋转、最多 20% 放大、±2% 平移 |
| 增强颜色变化 | 仅图片的亮度与饱和度因子在 0.8～1.2 内变化，标签不做颜色扰动 |
| 保持评价口径 | 仍是 256×256 等比缩放补边，标签最近邻插值，补边 255 不计分 |
| 保留对照与检查 | 旧权重可继续加载，新增采样、几何增强和迁移模型接口的回归测试 |

训练图中，植物至少占 0.5% 面积的有 180 张；原均匀采样抽到这类图片的概率约为 15.16%，混合采样后约为 19.62%。机器人类相应概率约从 5.90% 增至 11.24%。这些是采样分布的理论概率，不是给数据集增加新图片。原始像素标注仍较粗，外观相近的植物和珊瑚区域仍可能难以区分。

## 官方权重与环境

预训练权重由现有 torchvision 0.27 的官方枚举确定，下载地址：

[PyTorch 官方 LR-ASPP 权重](https://download.pytorch.org/models/lraspp_mobilenet_v3_large-d234d4ea.pth)

文件约 12.49MiB，保存在 checkpoints/pretrained；同目录 JSON 记录来源、字节数和完整 SHA-256。官方 HTTPS 来源是首要依据，指纹用于完整性核对；加载使用 weights_only=True。

[torchvision 官方说明](https://docs.pytorch.org/vision/0.27/models/generated/torchvision.models.segmentation.lraspp_mobilenet_v3_large.html)列出了预训练数据和归一化方式。该权重在 COCO 的 Pascal VOC 类别子集上训练；微调时输入使用对应的 RGB 均值和标准差归一化。原输出层替换为八类，SUIM 标签并未参与原来的官方预训练。

模型使用项目已有的 PyTorch、torchvision 和图像处理依赖。推理只需最终微调权重，不需要原始预训练文件或联网。

## 训练、模型选择与计算开销

本次使用 RTX 4060 Laptop 的 8GB 显存，批量大小 8，共训练 60 轮。最佳模型在第 52 轮，验证 mIoU 为 59.67%，旧模型最佳验证 mIoU 为 39.18%。最佳轮次固定后再做最终测试。

训练循环耗时约 855 秒，含缓存、模型准备及图表写出的脚本计时约 864 秒，即 14 分 24 秒，不包含 Python/框架启动。PyTorch 峰值已分配张量显存为 452.8MiB，峰值预留为 512.0MiB；这些数字不等于包含桌面程序、驱动和 CUDA 上下文的整机显存占用。实际训练说明这条优化路线可以在现有 8GB 显卡上完成。

选择最佳轮次的依据仍为验证 mIoU，而不是测试分数。训练后段训练损失继续下降、验证损失却上升，说明模型的泛化和置信度仍有改善空间；因此没有把“训练更久”直接当作“效果更好”。

在同一张缓存的验证图片、256×256、batch size 1、float32、预热 10 次后测量 50 次 GPU 前向：

| 模型 | 中位耗时 | P95 耗时 |
| --- | ---: | ---: |
| 旧 TinyUNet | 2.37ms | 2.67ms |
| 优化后的 LR-ASPP | 3.89ms | 4.96ms |

这是本机当前桌面负载下的短测，包含网络内部归一化和输出上采样，不包含读图、预处理、显存传入传出、恢复原图尺寸、视频编解码或网络传输。新模型计算稍慢，但单纯网络计算仍是毫秒级，不能把该数值直接当作完整视频系统的延迟。

对自己的图片预测：

~~~bat
python scripts\predict_segmentation.py --checkpoint runs\suim_transfer_20260911\segmentation_best.pt --input "path/to/underwater.jpg" --device cuda
~~~

输出虽恢复为原图大小，模型实际输入仍是缩小后的 256 像素图，不等于原生高清推理。

## 评价边界

这里比较的是模型结构、预训练、采样、增强和训练轮数共同变化后的结果，不能把提升完全归因于其中某一项；要确认单项作用，需要补做消融实验。

本次核对了两版的输入图、真值标签、分辨率、清单指纹和评价方法一致。测试集在第一版实验中已经被查看，当前仍只根据验证集选择模型；不能把这份测试集说成全新的未知外部测试。固定图片划分也不能保证严格的跨场景泛化。

这一步改善的是图片语义分割，还没有实现视频时序建模、语义码流或按重要程度分配视频码率。后续接视频时，需要同时测类别误判、帧间抖动和完整处理延迟，不能仅凭图片 mIoU 或网络前向耗时声称完成实时语义通信。
