# 图片与视频演示

## 启动

双击项目根目录的 **run_demo.cmd**。启动窗口保持打开，浏览器会自动进入 `http://127.0.0.1:8767/`。右上角显示“模型已就绪”后即可使用，首次启动需要几秒加载权重和预热。再次双击会打开已运行的页面。

带这台电脑现场展示时，无需联网、无需重新训练。建议接上电源，并先在出发前跑一次图片和短视频。

## 操作顺序

1. 保持默认参数，把一张水下图片拖到左侧框，也可点击框选择文件。拖入后自动开始。
2. 页面显示原图和预测叠加图。切换“纯色类别”，结合下方图例说明像素被分到了哪些类别。
3. 再拖一段 720p 或 1080p 短视频。处理完成后点“同步播放”，两侧会一起播放；右侧时间轴控制两侧定位。
4. 需要对比参数时，调整左侧设置，再点“用当前参数重新处理”。这个按钮使用当前选中的历史记录对应的原文件，刷新后也能用；每次建立新记录。
5. 点击“下载全部结果 ZIP”，或单独下载叠加图 / 视频、彩色类别图 / 视频和 JSON 报告。已经完成的记录可在“最近处理”里重新打开。

训练集以外的图片更适合展示泛化效果。官方测试图片已经参与过先前模型评估，应如实说明。导师提供的 `reconstructed.avi` 是重建视频，可用于演示处理流程，不应当作未经处理的外部原视频。

## 参数怎么选

| 参数 | 演示建议 | 作用 |
| --- | --- | --- |
| 模型输入边长 | 256 | 和本次训练一致。384 / 512 更耗时，可能保留细节，但不能保证识别更准 |
| 叠加颜色浓度 | 45% | 控制类别颜色覆盖原画面的浓度，不改变预测类别 |
| 视频帧间稳定 | 三帧投票 | 使用最近三帧类别图投票；可减轻跳变，但运动边界可能滞后 |
| 最多处理帧数 | 0 | 0 表示全部；长视频可先设 100 帧 |
| 保存每帧类别编号 PNG | 默认关闭 | 开启后保存无损 0～7 类别编号，便于后续统计；会增加文件数量 |

图片支持 JPG、JPEG、PNG、WebP、BMP。视频接受 MP4、AVI、MOV、MKV、WebM、M4V，能否解码还取决于文件中的编码与完整性。单文件最多 1 GiB，每帧 / 图片最多 1200 万像素。不支持摄像头或边上传边播放；当前界面是先处理素材，再对照播放。

模型对缩小后的图片推理，再将预测还原至输入尺寸。上传 1080p 不等于执行了原生 1080p 神经网络推理。

## 数据怎么看

- **模型前向**：仅神经网络前向耗时，CUDA 计时包含同步。图片只测这一次；视频报告逐帧平均值。
- **实际处理速度**：视频读帧、分割、投票、统计及写入三路视频的平均帧率，不含上传、模型启动预热、最终封装和 ZIP 打包。它不是网络传输帧率，也不代表连续实时链路的延迟。
- **处理与保存**：开始处理到保存预览的耗时，包含最终视频封装，不含上传、启动预热和 ZIP 打包。
- **类别占比**：图片的像素占比，或视频全部已处理帧合计的像素占比。没有真值标签，不报告本次素材的准确率、mIoU 或置信度。

这部分演示可以表述为：“已经训练了一个水下八类语义分割模型，并接通图片和视频的本地推理、可视化和结果保存。视频采用逐帧预测，可选因果投票稳定。后续可用这些类别图研究重要区域编码。”目前仍未实现完整语义通信。

## 本机文件

```text
run_demo.cmd                    双击启动
demo_server.py                  本机 HTTP 服务、上传与任务记录
console/                        静态页面，不使用外部字体或 CDN
scripts/demo_inference.py       图片 / 视频处理，复用现有分割函数
runs/demo_console/<记录编号>/
  job.json                      任务状态与参数
  source.jpg / source.avi ...    上传原素材副本
  result/
    input.png / input.mp4       输入预览
    overlay.png / overlay.mp4   预测叠加
    prediction_color.*         彩色类别预览
    prediction_index.png       图片的 0～7 类别编号
    masks/                     可选视频逐帧类别编号
    frames.csv                 视频逐帧耗时
    summary.json               统计、参数与说明
    results.zip                结果包，不包含上传原文件
```

上传不会修改原素材。任务按单队列处理，避免同时占满显存；最多同时有三个上传 / 等待 / 处理中的任务。点击“停止”会请求结束当前任务；中断结果不会作为成功记录播放。服务重启后保留完成记录，未完成任务标记为中断，需要重新拖入。

视频预览另外编码为 H.264 / MP4，输入画面预览也是重编码副本；没有保留声音。奇数宽高会补齐至偶数，源帧率缺失时会提示并用 30 FPS，可变帧率输入按名义帧率播放。彩色视频有显示用的压缩损耗，要读精确类别应使用编号 PNG。

页面列出最近 15 条记录，服务接口返回最近 30 条；更早的结果仍在磁盘目录中。项目不会自动清理这些素材和结果，也不会上传到 GitHub。

## 权重与 FFmpeg

默认使用 `runs/suim_transfer_20260911/segmentation_best.pt`，即本机已经训练好的 LR-ASPP + MobileNetV3 模型。只读取本机权重，推理时不会自动下载预训练文件。

Web 服务只使用 Python 标准库；模型仍使用项目已安装的 PyTorch、Pillow、NumPy、OpenCV。没有另装 Web 框架。

视频预览需要带 `libx264` 的本机 FFmpeg。本次复用了此前视频项目中已安装的版本，并放入 `tools/ffmpeg/bin/ffmpeg.exe`，无需重新下载。程序按以下顺序找可执行文件：

1. `--ffmpeg` 或环境变量 `FFMPEG_PATH`。
2. 当前项目 `tools/` 下的 FFmpeg。
3. 系统 PATH 中的 `ffmpeg`。
4. 同一 `works` 目录下的 `Python/video-baseline/tools/`，用于兼容此前的安装位置。

找不到 FFmpeg 时仍可处理图片，视频上传会给出提示。环境、模型权重、数据和 `tools/` 都被 `.gitignore` 排除，新克隆的仓库不能直接代替这台电脑上完整的演示环境。

若需要改端口或权重，可在项目环境命令行执行：

```bat
python demo_server.py --port 8768 --checkpoint "runs\你的训练目录\segmentation_best.pt" --ffmpeg "工具目录\ffmpeg.exe" --open
```

服务只监听 `127.0.0.1`，不开放局域网访问。若浏览器打不开，先检查启动窗口的报错和端口；不要关闭启动窗口后继续等待页面恢复。
