# 联合语义源编码实验

## 为什么改这条链路

普通图片压缩之后再运行语义分割，只能评价压缩对识别的影响。它没有让语义参与编码，不能作为本项目已完成语义通信的依据。这条普通链路保留为参考，新增一个水下任务导向的联合源编码模型。

发送端先用固定的 SUIM SegFormer-B0 预测八类语义。RGB 和预测类别的 one-hot 表示一起进入编码器，经量化、超先验和 rANS 熵编码写入 `.svic`。接收端从文件解出量化潜变量，使用共享图像解码特征，分别输出 RGB 与八类类别 logits。类别图来自这个解码头，而不是对还原图片再次运行 SegFormer。

文件中只包含尺寸、版本、模型校验信息和两组熵编码流。原图、发送端类别 PNG、SegFormer 权重、联合模型权重均不随单张文件发送；双方预先部署同一份联合权重。演示目录里的原图和类别 PNG 是报告附件，不属于传输码量。

## 模型和训练

以官方 CompressAI `bmshj2018-hyperprior` q3 权重初始化。编码器首层由 3 通道扩展到 11 通道：3 个 RGB 通道加 8 个预测语义通道。RGB 卷积权重沿用预训练值，新增语义通道初始化为零，通过联合训练学习。图像解码器的 1/4 尺度特征分出一个类别头，输出双线性上采样后的八类 logits。

它是本项目实现的最小联合模型，使用开源压缩与分割组件；不是作者发布的完整语义通信网络，也不是 GLC、SQ-GAN 或 TOSC 复现。相关论文支持任务导向源编码这条研究路线，但不能作为本模型性能的证据：

- [Task-Oriented Image Semantic Communication Based on Rate-Distortion Theory](https://arxiv.org/abs/2201.10929)：在码率约束下同时考虑图像与任务相关语义失真。
- [SQ-GAN: Semantic Image Communications Using Masked Vector Quantization](https://arxiv.org/abs/2502.09520)：语义条件参与特征选择与源编码；其工作只作用于源编码部分。本项目没有实现它的向量量化、SAMM 或 GAN。

当前训练目标为：

`L = R + 0.0067 × 255² × MSE + 1.0 × L_sem + 0.15 × L_teacher`

- `R` 是潜变量与超先验的负对数似然，按有效图片像素归一；训练时是码率估计，不含实际文件头。
- `MSE` 约束 RGB 还原，补边像素不计入图像失真。
- `L_sem` 是接收端直接类别输出对人工标签的误差，使用 0.7 类别加权交叉熵与 0.3 Dice。它反向更新编码器、熵模型及共享解码器。
- `L_teacher` 是对发送端预测类别的辅助交叉熵蒸馏项。SegFormer 冻结，其预测是编码条件；人工标签只用于监督，不输入编码器。

这次固定使用原 SUIM 划分：训练 1187、验证 297、测试 110。输入为 256×256 等比缩放加中心补边，标签补边为 255 且忽略。类别权重只按训练集统计。第一轮只预热类别头，随后 11 轮联合训练；batch size 2，编码主干学习率 1e-4、类别头 1e-3、熵模型 quantiles 辅助优化器 1e-3。最佳轮次按联合验证目标选择，110 张测试图没有用于本轮训练、选择或报告。

运行命令（项目根目录）：

```powershell
.\.venv-segformer\Scripts\python.exe -X utf8 scripts\train_semantic_codec.py --output runs\joint_codec_new --epochs 12
.\.venv-segformer\Scripts\python.exe -X utf8 scripts\evaluate_semantic_codec.py --checkpoint runs\joint_codec_new\semantic_codec_best.pt --output runs\joint_codec_new_validation
```

输出目录必须是新目录，以免覆盖旧实验。训练与发送端分割可用 GPU；实际熵编码及解码统一 CPU，避免设备浮点计算差异使 rANS 解码失步。环境沿用 `.venv-segformer` 与图片编码环境，没有新增下载来源。

## 本机实测（2026-10-02）

12 轮用时约 319 秒。训练程序记录的 GPU 显存分配峰值约 324 MiB，这只统计该进程的 PyTorch 分配，不是整台电脑的显存总占用。选中第 6 轮权重后，对全部 297 张验证图实际编码文件并从文件解码。

| 验证项 | 结果 |
| --- | ---: |
| 发送端 SegFormer 对真值的 mIoU | 62.91% |
| 联合码流直接解码类别的 mIoU | 61.36% |
| 普通 q3 还原后再分割的参考 mIoU | 50.79% |
| 联合模型平均完整文件 | 2565.93 B |
| 普通 q3 平均完整文件 | 2496.59 B |
| 联合模型平均完整文件 bpp（256²） | 0.3132 |
| 联合 RGB 有效像素 PSNR | 29.90 dB |
| 普通 q3 RGB 有效像素 PSNR | 30.37 dB |

类别指标在整套验证图上累计混淆矩阵，含水体背景，忽略补边 255。PSNR 使用跨图片累计的有效像素 MSE；完整文件 bpp 使用整个 256×256 画布，并包含文件头。训练 likelihood bpp 与完整文件 bpp 的分母和计量内容不同，不能直接混用。

普通 q3 是通用预训练参考，没有在相同 SUIM 数据与训练预算下微调，且没有专门的类别解码头。因此这张表不是严格的架构消融，不足以声称相同码率下全面优于普通压缩。本轮联合文件平均增加约 2.78%，RGB PSNR 略低；结果显示的是语义保留与像素还原之间的取舍，尚未证明码量优势。验证集也参与选轮次，最终泛化结论仍应留给独立测试集。

语义参与的两项检查：

1. 只反传人工类别损失，不使用像素损失，编码器 RGB 与语义输入通道均产生非零梯度。
2. 保持 RGB 和模型不变，把首张固定验证图的发送类别循环移位，实际熵编码 payload 随之改变，接收端有效区域类别中约 52.76% 改变。这是条件依赖检查，不是准确率或压缩效率提升的证明。

报告与真实文件保存在：

- `runs/suim_joint_semantic_codec_20261002/`：权重、配置、每轮记录、语义梯度检查。
- `runs/joint_semantic_validation_20261002_verified/`：最终代码下全部验证图的普通／联合码流、解码结果、逐图 CSV、对照图与汇总。早先的同名无 verified 目录保留作过程记录。
- `runs/image_codec_console/`：页面 720p 文件传输记录。

720p 的鲨鱼与潜水员图片，联合文件为 16597 B、0.1441 bpp，RGB PSNR 36.52 dB、SSIM 0.9678。20 kbps 的实际应用层平均发送速度为 19.95 kbps，传输约 6.69 秒；40 kbps 的平均发送速度为 39.89 kbps，约 3.35 秒。该图片没有人工真值；两端类别一致比例约 97.07% 只是发送预测与直接解码的比较。720p 按原尺寸编码，训练只见过 256 输入，其结果属于跨分辨率试用，不能替代验证指标。

独立进程接收端只加载收到的 `.svic` 和联合权重，输出与页面的 RGB、类别索引逐像素一致；发送和接收文件的字节也完全一致。检查记录为 `runs/joint_semantic_independent_20261002/verification.json`。最终自动测试通过 39 项，涵盖语义梯度、独立双输出解码、文件完整性、限速传输与页面接口。

## 页面与独立接收端

双击 `run_semantic_codec_demo.cmd`，页面地址为 `http://127.0.0.1:8769/`。选择“联合语义编码”、传输限速后拖入图片。查看“还原图片”“直接解码类别叠加”“两端类别”，可下载 `.svic`、还原 PNG、类别索引和报告。类别图可单独用于水下任务，不依赖展示用 RGB。

当前只有一份联合训练权重，发送端语义输入固定为 256，普通压缩的 1／3／5 档不用于这个模型。切换发送速度不改变模型与压缩内容，只改变等待时间。若端口已有不匹配的旧服务，请关闭对应启动窗口后重开，或使用 `--port 8770`。

接收端不需要分割权重或原图，命令如下：

```powershell
.\.venv-segformer\Scripts\python.exe -X utf8 scripts\semantic_image_codec.py decode --input received.svic --output reconstructed.png --semantic-output classes.png --checkpoint runs\suim_joint_semantic_codec_20261002\semantic_codec_best.pt
```

发送端命令：

```powershell
.\.venv-segformer\Scripts\python.exe -X utf8 scripts\semantic_image_codec.py encode --input photo.png --output encoded.svic --checkpoint runs\suim_joint_semantic_codec_20261002\semantic_codec_best.pt --segmentation-checkpoint runs\suim_segformer_b0_20260915\segmentation_best.pt
```

文件只通过 TCP 传送，20～40 kbps 按发送方向应用层文件与传输头限速，允许多花时间传完；未统计 TCP/IP、链路头和反向 ACK。`.svic` 包含实际量化和熵编码数据，输出 PNG 或结果 ZIP 的大小不算通信码量。

## 下一步验证

这轮满足“语义影响编码，并从码流恢复任务输出”的结构要求，可描述为理想信道下的任务导向语义源编码原型。是否符合导师希望采用的某个具体语义通信方法，仍要按导师指定的任务、论文与评价指标对齐，不能把普通神经压缩或本项目实现泛称为完整论文复现。

后续应先做同划分、同训练预算的去语义条件／去语义损失对照，再训练几个码率权重，画出实际文件码量、真值 mIoU 和 RGB 质量的曲线。图像结果确认后再加视频帧间潜变量与关键帧编码。真实水声信道、噪声、丢包、联合信源信道编码都尚未实现。
