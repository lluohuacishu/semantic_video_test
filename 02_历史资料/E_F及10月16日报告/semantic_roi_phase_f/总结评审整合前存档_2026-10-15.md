# 阶段F：首轮总结与后续方向

日期：2026-10-15。本轮完成概率诊断、61个人工框覆盖核对，以及冻结阶段E在一个新保留视频上的实际收发对照。阶段F首轮范围到此结束；项目的可靠目标保护仍未完成。

## 1. 项目现在到哪里

目标保持不变：**有限带宽下恢复可观看视频，语义信息用于保护关键目标。**

视频输入、预测提取、分层编码、完整文件、限速TCP、独立接收和视频恢复已经能运行。阶段E改变了ROI空间组织，阶段F没有新增网络、训练模型或修改生产算法，而是检验现有方案在哪里失败。

目前可以交付可操作的工程原型和可复核结果，仍不能声称低码率下可靠保护了鱼类，或已在独立水下场景中优于普通H.265。

## 2. 三步工作得到了什么

| 工作 | 实测结果 | 对当前路线的含义 |
|---|---|---|
| 步骤1：video131漏保护诊断 | 435、450帧GT处最大鱼概率约0.687、0.571，均未到0.9；恢复两帧自身被64像素过滤的连通域也不能覆盖这些鱼 | 问题早于最终ROI组织，但不能仅凭这几帧就下调全局阈值 |
| 步骤2：61框逐项统计 | E有39框达标、2框部分覆盖、20框完全漏保护；38个含框帧中仅18帧的所有框都达标 | 框面积平均值会掩盖目标遗漏，小目标和边缘目标需要逐项检查 |
| 步骤2：码流开销核对 | video131左侧条带40,102B，占ROI流字节52.47%，32帧内未与已核对框相交 | 误检位置会消耗真实预算；尚未通过删流实验证明可等质量省掉这些字节 |
| 步骤3：冻结E的新视频对照 | video6两段各50帧，E/H.265分别完成真实20kbps收发和独立恢复，文件预算差均小于1% | 工程迁移成功，算法任务收益仍需看实际GT结果 |

## 3. 新视频检验的关键负结果

新视频来自公开video7.zip的实际video6目录。它属于官方train划分，但没有用于本项目的训练、阈值或方法选择；拍摄级独立性尚未确认，所以称为本项目新保留视频，不称官方测试集。

先固定0—49帧，发现4张发布者GT均无鱼后仍保留该结果。再预先固定“首个≥50的含鱼GT锚点”规则，补测50—99帧；两段不重叠，但来自同一个视频。含鱼片段有3张GT，合计2,010个鱼像素、10个像素连通域，不能当作10条经确认的独立鱼。

| 含鱼片段50—99 | E | 普通H.265 |
|---|---:|---:|
| 完整传输文件 | 99,269B | 98,551B |
| 实际20kbps发送 | 39.750秒 | 39.469秒 |
| 接收恢复帧 | 50 | 50 |
| 全局RGB PSNR | 30.61dB | 34.00dB |
| GT鱼区PSNR | 34.06dB | 32.26dB |
| 鱼类IoU | 0 | 0 |
| 鱼类召回率 | 0 | 0 |

原图鱼IoU为25.80%、召回率为30.60%。E覆盖了1,940/2,010个已标注鱼像素，即96.52%，9/10个GT连通域完全进入ROI；一个70像素连通域完全漏保护。

**这里同时有两类问题：目标仍有漏保护；大部分目标即使进入ROI、局部PSNR改善，当前分割模型仍无法在重建图上识别。** E的鱼区PSNR比H.265高约1.79dB，全局PSNR却低约3.38dB，任务收益没有出现。不能再将“ROI更小”“鱼区PSNR更高”单独当作语义保护成功。

初始0—49片段中，E在4张无鱼GT上无鱼类误报，H.265有3,440个误报像素；E全局PSNR仍低约4.24dB。这是负样本上的固定模型行为，不足以证明目标更清楚。其余未标注帧不能当作已确认无鱼。

所有指标来自实际接收端RGB，全部流、消息和封装都计入文件。约40秒的发送时间不含识别、搜索和恢复；每段仅名义播放2秒，当前原型仍为离线批量收发，尚无真实水声链路实验。

## 4. 后续只推进一条小修复线

下一步先用本轮全部既定目标做小规模人工可辨识性检查，确认模型识别为零时，人能否发现目标、辨认轮廓。原图也要同等检查。已知GT位置的局部看图与无提示目标发现分开评价，隐藏编码方法、统一尺度；当前报告里的对照截图还不是盲评结果。

随后只改一个因素，优先做**背景与ROI预算分配的小对照**，保持发送端模型和候选规则固定，同时观察目标周围上下文。现有方案固定低清背景CRF42，追加预算主要进入ROI；在新视频中，平均ROI面积从2.82%到34.98%都有出现，几何面积和实际码量都需一起约束。

下一轮必须同时检查目标覆盖、局部质量、背景质量、任务表现和无鱼误报。融合边界、上下文变化、压缩误差与0.9阈值稳定性对识别失败的作用尚未分离，不预设单一原因，也不增加新网络。

video6若开始参与新方法选择，应作为开发数据；修复后的方案再另留未参与选择的视频检验。阶段C的MLVC多帧训练仍保留为研究分支，不阻塞当前视频原型。
