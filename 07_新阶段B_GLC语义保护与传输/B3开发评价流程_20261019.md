# B3 开发评价流程（2026-10-19）

按用户对开发阶段效率的反馈调整：质量开发不再以每个片段完成 20／30／40 kbps 限速发送为前提。本文件覆盖旧续接记录中的“先补齐三档再评价”安排；历史实验及未完成状态保留原样。

## 为什么调整

当前发送器对同一个已编码文件按应用层字节计时发送；接收器完整收齐、核对哈希之后才开始解码。20／30／40 kbps 不改变编码配置、发送内容或解码输入，也没有模拟丢包、误码、断连、时延分布或水声信道。现有同机回环的作用是软件集成验证：封装、收发、校验、独立解码和读取边界；不是通信鲁棒性验证。

B0+B1、B2 和开发片对照已验证过这个软件流程。把每个新素材的三档完整等待作为质量评价的必经步骤，带来的主要是重复等待和重复解码，应从当前开发流程移除。

## 当前执行规则

1. 当前四段候选均已有 40 kbps 正式通过的独立解码结果。质量评价直接复用各一份已验收 RGB，仍核对包、源文件、帧序与 RGB 哈希；不重新发送或解码，不必补齐尚缺档位。
2. 评价输入必须注明“单次已验收解码”，不能据此生成三档通过记录。限速实测日志保持原样，理论等待时间和实测时间分列。
3. 后续新编码方案默认只需从最终包做一次独立解码，再做质量、时序、预测区域覆盖及完整字节预算评价。开发文件交接应直接复制并校验，或在协议联调需要时做一次不限速回环；不能把本地复制标成实际 TCP 收包。当前入口先支持已有正式通过结果，新的离线解码入口按实际需要补充。
4. 只有修改传输协议、封装／接收边界、限速器，或明确进入链路验收时，才单独执行相应网络回归。小包与虚拟时钟可用于限速调度单测；不自动对每个素材补跑三档。
5. 本次不启动新的整段限速传输、GPU 解码或完整视频评价。准备单次评价输入并验证入口后停止，后续直接进入质量诊断。小包协议单测仍可执行。

## 20／30／40 的保留用途

它们是三个假设的应用层发送速率，不是三种视频编码码率或质量档位。开发阶段用真实包大小换算理想发送耗时即可：

`估算秒数 = 8 × 应用层发送字节 / (1000 × kbps)`

应用层发送字节含文件和发送方向协议头。该估算不含 TCP/IP／链路层与 ACK 开销、不含重传、连接建立、编码或解码耗时，不是实际网络测量。若只有文件字节，则只能标注为文件有效载荷时间估算。

Drina 的原实测应用层字节为 4,177,700 B，相应理想发送时间为 1,671.080／1,114.053／835.540 秒（约 27.85／18.57／13.93 分钟）。这个数字可以直接计算，不必为每次质量实验真实等待。

当前没有截止时间、丢包模型或自适应码率机制；因此不把三档分别当作三个质量实验。将来若研究这些机制，再明确变量和实验目的。

## 已实现入口与下一次执行

`public_diagnostic_input.py` 从正式通过的单档结果建立评价输入，核对原始 TCP 收包、发送确认、包哈希、完成记录、读取审计和结果身份。它不发送或解码，只记录现有输出位置和理论发送耗时。`evaluate_b3_public.py --input-summaries` 接受这些输入，并在实际评价时逐帧核对 RGB；旧 `--network-summaries` 参数及三档汇总仍可用。

四个输入保存在工作区 `work/stage_b_20261019_b3_public_inputs`，分别为 `kanagawa.json`、`redsea.json`、`madeira.json`、`drina.json`。均选择已有40 kbps正式通过结果；这只说明所复用文件的来源，不把40 kbps设为新的开发限制。

下一次从仓库根目录执行下列命令即可直接评价（本轮不运行）：

```powershell
$b3 = '07_新阶段B_GLC语义保护与传输'
$baseline = Get-Content -LiteralPath "$b3/configs/b0_baseline.json" -Raw -Encoding UTF8 | ConvertFrom-Json
$glcPython = $baseline.runtime_dependencies.glc_python
$workspace = (Resolve-Path '../../..').Path
$inputs = Join-Path $workspace 'work/stage_b_20261019_b3_public_inputs'
$summaries = @('kanagawa','redsea','madeira','drina') | ForEach-Object { Join-Path $inputs ($_ + '.json') }
$output = Join-Path $workspace 'work/stage_b_20261019_b3_public_diagnostics'
& $glcPython -B "$b3/evaluate_b3_public.py" --input-summaries $summaries --registry "$b3/B3公开视频候选来源_20261018.json" --output $output
```

输出目录必须尚不存在；若有后来创建的结果，先检查后选择新的目录，不覆盖结果。代码要求工作区干净。入口验证通过4段共750帧的既有解码记录，并兼容Kanagawa旧三档汇总；41项单测通过。完整逐帧质量评价与视频生成尚未在此轮执行。

## 保留的研究问题

GLC 和自动语义 ROI 对鱼纹、轮廓、动作及时间连续性有什么影响；收益是否仅由增加字节产生；固定区域及全画面控制是否达到预算匹配。四段公开候选不能保证预训练独立性，预测不是 GT，用户尚未观看评分。这些口径不因简化传输流程而放宽。
