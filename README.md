# 水下视频语义通信

更新：2026-10-29。本分支 `codex/glc-sender-no-rgb` 从蒸馏第二轮结果 `073c45a` 分出，当前优先研究**水下发送端免 RGB 重建**。水下 AI 盒子负责编码，船上/岸上接收端使用完整原 GLC 重建可观看视频；允许离线处理。先读[发送端研究入口](13_优化阶段_发送端免RGB重建/README.md)。

`codex/glc-distillation` 分支及两轮训练权重、代码和视频原样保留，暂停第三轮 RGB 生成器蒸馏。[蒸馏研究入口](12_优化阶段_GLC蒸馏/README.md)、[可行性调研](05_资料与索引/GLC蒸馏调研_20261028/调研报告.md)和[本机训练耗时预估](05_资料与索引/GLC蒸馏耗时预估_20261029/耗时预估.md)是已完成探索的记录。

最新[发送端免RGB实测](13_优化阶段_发送端免RGB重建/发送端免RGB实测_20261029.md)：三个设置各三组配对，编码核心约快2.21–2.23倍；228帧独立恢复的RGB与原模型一致，训练步数为0。压缩载荷不变，新容器净增55B；当前仍加载完整权重，显存未下降，Orin和功耗未测。

最新[第二轮实测](12_优化阶段_GLC蒸馏/round2/第二轮结果_20261029.md)：盘点本机54段、24,115帧，训练覆盖49个文件、3,052个去重P帧；1099万参数学生四组各5000步，共约47分钟。候选解码核心约快2.05倍，旧回归片改善，但新场景色偏与细节仍不合格，当前不能作为可用替换。[首轮结果](12_优化阶段_GLC蒸馏/先导试验结果_20261029.md)保留历史记录。项目仍要求恢复可观看视频；最终面向 Orin，目标是减少文件编码、传输、接收重建的总等待，不要求实时播放。

既有[纹理稳定性首轮对照](11_优化阶段_纹理稳定性/README.md)已完成，两段开发片的轻量因果滤波有数值改善，观看结论待评价；本机对比页配置为 `http://127.0.0.1:8780/`。纠错留后，旧实验不为切换分支而重跑。
