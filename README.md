# GLC 水下视频压缩与后处理

更新：2026-11-07。`main` 为当前主线，汇总已验证的 GLC 编解码加速代码、实验报告和小型证据。下一阶段聚焦 **GLC 重建 RGB 的后处理优化**，改善生成纹理的时间稳定性；目前尚未证明解决画面晃动。

原型面向水下端编码、岸上 GPU 独立恢复视频。当前以 Windows / NVIDIA GPU 为验证平台，保留原权重与 FP32 参考链，提供可显式选择的 TensorRT 加速方案。Orin 实机、能耗和真实水声链路仍待验证。

## 当前能力

- 实际生成 GLCSND 码流，接收端不读取源画面，执行独立熵解码与逐帧参考一致性校验。
- 发送端省去非必要 RGB 重建，按角色裁剪加载权重，并分别优化输入编码器与最终 RGB 生成器。
- 输入编码器支持原版 FP32 和 TensorRT 等执行方案；RGB 生成器支持原版 FP32、TensorRT FP32 和保护混合精度。
- 本机研究网页支持完整视频至 EOF、原帧率或半帧率、码流大小与真实平均码率、耗时和重建观看。原版 FP32 仍为保守基线，加速需显式选择。
- 保存无损 RGB、逐帧指标、真实码流及来源校验；观看 MP4 的大小不作为神经压缩码率。

## 完整视频实测

本机 RTX 4060 Laptop，原片完整取样 **1239 帧 / 15 FPS / 82.6 秒**，GLC q0、GOP64、reset32。加速为输入编码器 `trt_fp16_stream` + RGB 生成器 `trt_fp16_safe`；熵与参考路径保留 FP32。

| 分辨率 | 执行方案 | 编码核心时间 | 解码核心时间 | 完整码流平均码率 |
|---|---|---:|---:|---:|
| 512×288 | 原版 FP32 | 86.62 s | 126.47 s | 26.2210 kbps |
| 512×288 | 编解码加速 | 40.89 s | 87.39 s | 26.2222 kbps |
| 640×360 | 原版 FP32 | 119.88 s | 181.23 s | 34.6734 kbps |
| 640×360 | 编解码加速 | 56.03 s | 122.03 s | 34.6547 kbps |

时间不含全部模型加载、媒体准备与输出开销；15 FPS 是播放时基，不能据此认定处理达到实时。单次本机实验不代表其他 GPU 的性能，历史不同阶段的加速倍率不可连乘。

详细设置、独立恢复校验及全部阶段耗时见 [完整视频实测](20_优化阶段_编解码执行复核/完整82秒_15FPS双分辨率实测_20261105.md)。

### 感知质量

以下均以同分辨率的**编码前无损源 RGB**为参照，对完整序列逐帧测量；LPIPS / DISTS 越低越好。

| 分辨率 | 执行方案 | LPIPS-Alex ↓ | DISTS ↓ | RGB PSNR ↑ |
|---|---|---:|---:|---:|
| 512×288 | 原版 FP32 | 0.138711 | 0.151466 | 22.1352 dB |
| 512×288 | 编解码加速 | 0.138945 | 0.151121 | 22.1421 dB |
| 640×360 | 原版 FP32 | 0.140013 | 0.140337 | 22.4616 dB |
| 640×360 | 编解码加速 | 0.140236 | 0.140120 | 22.4587 dB |

平均指标变化很小且方向不同，不能表述为加速“无损等价”或画质整体提升。两种重建的局部纹理确有变化，主要来自编码端 FP16；固定同一码流时，解码保护混精单独引入的影响小得多。这些逐帧图像指标也不能证明闪烁减少或运动更流畅。

指标协议、FP32 对照、逐帧 CSV 和像素差异见 [完整感知质量报告](20_优化阶段_编解码执行复核/完整82秒_15FPS_FP32与加速感知质量对照_20261105.md)。

## 下一阶段：GLC 后处理

保留现有编码、熵解码和参考更新机制，在**解码后的 RGB、观看 MP4 编码之前**接入后处理。使用原版与加速的无损 RGB 作为独立基线，输出到新实验目录，评估画质、时序稳定性及新增处理开销。

已有接口为 `decoded_rgb.npy` 或 `decoded_chunks/*.npy`，RGB / uint8 / THWC。分块存储末块预分配64帧，读取时须按存储元数据 `chunks[].frames` 截取有效帧，避免把填充计入900帧或1239帧。后处理结果不回灌 GLC 的参考链。

本地入口为工作区 `01_项目/GLC后处理/`，已索引900帧、完整82.6秒、两档分辨率及 FP32 / TRT 基线。当前未开展新的后处理训练或算法实验。
