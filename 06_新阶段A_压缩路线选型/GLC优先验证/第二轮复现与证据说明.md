# GLC 第二轮：复现与证据说明

本轮只新增试验编排、评价与展示脚本。GLC 官方网络、官方预训练 I/P 权重和前轮真实码流适配器继续复用；没有训练新模型，也没有改写编解码器。四个适配文件与仓库 `04_外部依赖快照/semantic-video-training/scripts` 的 SHA256 一致，见最终 evidence 中的 `environment_provenance.json`。

## 1. 环境和输入

- 编码、评价和拼图使用既有 `semantic-video-training/.venv-glc`：Python、PyTorch 2.5.1 + CUDA 12.4、torchvision、OpenCV、NumPy、Pillow。绘图使用既有 `semantic-video-mlvc/.venv` 的 matplotlib。
- GPU：本机 RTX 4060 Laptop 8 GB；GLC 同机 FP32 确定性解码。跨设备解码兼容性没有在本轮测试。
- GLC 上游固定在 `126db25f9c093508cd0c99cee32b53fd60074f9a`。本地 `.glcv` 是研究用 rANS 容器，不是作者发布的官方码流格式。
- 原始素材、发布者鱼类 mask、I/P 权重、工具二进制沿用本地旧工程。仓库不打包这些大文件；单独克隆仓库不会自动获得完整运行环境和素材。
- DISTS 使用该 GLC 快照自带实现与校准参数，VGG16 取自 `https://download.pytorch.org/models/vgg16-397923af.pth`。缓存位于输出目录 `assets/torch/hub/checkpoints`，完整 SHA256 见证据。整段通信成本不含预共享模型首次分发费用。
- 图像均为 1280×720 RGB 源图。工作分辨率降低使用 OpenCV AREA；评价和展示均使用 Pillow LANCZOS 统一恢复到 720p。原始 JPEG 本身已有压缩；本轮不把它称为无损摄像机原始数据。

| 输入 | 源帧，0基索引 | 帧率 | 时长 | GT 使用范围 |
|---|---|---|---|---|
| short / video6 | 50–99，共50帧 | 25，沿用名义值 | 2秒 | 60、75、90三帧，合计2,010鱼区像素 |
| long108 / video108 | 0–249，共250帧 | 25，沿用名义值 | 10秒 | 现有17张GT均无鱼区正像素，不计算鱼区PSNR |
| long91 / video91 | 0–249，共250帧 | 15，沿用来源时间记录 | 16.67秒 | 17张有鱼GT，合计42,459鱼区像素 |
| long24 / video24 | 0–249，共250帧 | 25，沿用名义值 | 10秒 | 现有17张GT均无鱼区正像素，不计算鱼区PSNR |

没有正像素只表示所用GT没有相应正标注，不等于所有视频帧都没有鱼。四组均来自已使用的开发资料，尚未证明摄录来源相互独立，也没有确认的潜水员验收场景。

## 2. 执行顺序

在 PowerShell 中按本机位置填写这些路径。`$out` 必须指向仓库外的新输出目录；第一次复现不要复用本轮证据目录。

```powershell
$glcPython = '<原训练工程>\.venv-glc\Scripts\python.exe'
$plotPython = '<原主工程>\.venv\Scripts\python.exe'
$project = '<原 semantic-video-mlvc 根目录>'
$legacy = '<原 semantic-video-training 根目录>'
$ffmpeg = '<ffmpeg.exe 的绝对路径>'
$previous = '<前轮 codec_pilot 目录>'
$out = '<仓库外的新输出目录>'
$here = '<本 README 所在的 GLC优先验证 目录>'
$oldEvidence = '<06_新阶段A_压缩路线选型\evidence>'
$evidence = '<本轮小型证据输出目录>'

foreach ($clipName in @('short','long108','long91','long24')) {
    foreach ($phaseName in @('prepare','glc','standards','evaluate')) {
        & $glcPython "$here\run_round2.py" $phaseName --clip $clipName `
            --project $project --legacy $legacy --previous $previous `
            --output $out --ffmpeg $ffmpeg
        if ($LASTEXITCODE -ne 0) { throw "阶段失败：$clipName / $phaseName" }
    }
}
& $glcPython "$here\verify_round2.py" --run $out
& $glcPython "$here\make_round2_gallery.py" --run $out --output $evidence `
    --previous-evidence $oldEvidence --ffmpeg $ffmpeg
& $plotPython "$here\plot_round2_diagnostics.py" --run $out --output "$evidence\figures"
```

`--previous` 保留前轮编排接口，本脚本实际不读取该目录；所有本轮输入均由 `prepare` 从指定工程源图生成。当前实验为减少等待并行运行部分 CPU 编码和 GPU 编码，所以记录的耗时仅作资源记录，不用于严格的编码速度排名。GPU 编码和 DISTS 评价排队运行以避免争抢显存。

完成的编码根据 `verified.json` / `selection.json` 跳过，完成的评价根据 `metrics.json` 跳过。**如果改变输入、参数或评价实现，应使用新输出目录**；不要沿用旧缓存后把新脚本名当成新结果。部分失败目录不会被自动清空或覆盖，应先检查日志、归档后再重跑。

本轮首个720p短片编码由直接命令启动，顶层encode命令日志未单独保存；它复用了前轮同RGB无损输入，随后逐帧核对了本轮统一输入与发送/接收端像素。其文件头、完整文件、输入哈希和解码验证均保留；不伪造缺失的顶层命令或耗时记录。

## 3. 计量口径

- `file_bytes` 为实际完整文件大小，包含容器和校验元数据。每个 GLC 目标匹配 H.265 slow / AV1 cpu-used6 的实际 MP4 文件；不补零，不截断流，不按画质挑 CRF。
- AV1 使用 `-g GOP -keyint_min GOP`，H.265 使用固定 keyint、关闭 scenecut。最终 ffprobe 检查实际帧数及关键帧位置，详见[试验约定中的关键帧修正](第二轮试验约定.md)。没有命中 ±2% 的结果必须单独标记。
- 图示单位为十进制 KB，1 KB = 1,000 B。纯文件传输等待 `8 × file_bytes / (1000 × 链路kbps)`，不含处理、协议、重传时间。本轮没有新做网络实传，也不把压缩视频平均码率误作20–40 kbps链路限制。
- RGB PSNR 按全帧累计平方误差计算，鱼区PSNR仅累加有GT的像素；MS-SSIM逐帧计算再平均。没有GT正像素的鱼区结果保留 null。
- DISTS 在720p计算，不缩成256p；短组全部50帧，长组使用预先固定的采样集合（每10帧、正鱼GT帧、I/reset候选位置前后1帧并集）。同一长片的 GOP64 / 128 使用相同集合。该设置服务本轮内部比较，不能直接混用其他缩放设置下的论文绝对分数。
- 每个片段先检查原图与自身的 DISTS≈0、MS-SSIM≈1。逐帧值、采样索引、实现和权重哈希均保存，不能只凭一个汇总均值认定语义保真。
- `temporal_error_delta_mae_8bit` 是相邻帧“重建减原图”误差的变化量。它会受运动和重建特性影响，是定位异常的诊断量，**不是感知闪烁评分**。

## 4. 交付和验收

预定矩阵共25个最终编码点：短组13点；long108六点；long91、long24各三点。其中7个GLC文件共1,150帧，每帧要求发送端与独立接收端的 latent/RGB 校验一致，接收端不读取源图。普通编码共18个点，保存 CRF 搜索轨迹、最终字节偏差和真实关键帧位置。

- 仓库：脚本、协议、报告、环境哈希、小型 JSON 证据、固定取帧对照和曲线。旧证据保留。
- 本地：模型、原图、候选码流、最终完整码流、逐帧解码PNG、运行日志、连续播放副本。`gallery/index.html` 是观看入口。
- 连续播放副本使用 libx264rgb CRF0 保存显示RGB，并逐份解码计算RGB SHA256，与送入预览编码器的全部像素校验一致。播放器兼容性以本机为准。该观看副本的体积不能用于通信预算；评价只读解码PNG。仅生成观看副本时可对拼图脚本追加 `--playback-only`，无需等待指标完成。
- 图片固定展示源帧90、三张GT中所有连通目标、长片首/中/末帧、索引64前后的连续局部。它们不能替代正常速度播放和真实人工评分。
- 本轮没有生成任何人工偏好/识别率分数；正式盲评、来源独立的留出场景、潜水员目标、跨设备实传仍须另外验收。
