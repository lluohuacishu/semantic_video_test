# 新 A · GLC 第二轮：低预算与连续片段

2026-10-17，产生本轮质量结果前记录。复用官方预训练 GLC 和既有真实文件适配器，不训练，不覆盖前轮证据。

1. 先在 video6 源帧 50–99、名义 25 fps 上运行 q0 / reset32 / GOP64 的 720p、540p、360p 三点。GOP128 在这个 50 帧输入上与 GOP64 没有额外 I 帧差异，不重复运行。前轮 720p / GOP32 原始结果作为已完成的参照。
2. 统一从相同 RGB 源图下采样，使用 OpenCV INTER_AREA；所有低分辨率结果用同一 Pillow LANCZOS 还原到 720p 后评价。GLC 和普通编码器读取经过哈希验证的相同工作图像。评价不使用二次编码预览。
3. 每个真实 GLC 文件，匹配 H.265 slow 和 AV1 cpu-used6 的完整文件大小：同时保留原生 720p 和相同工作分辨率对照，720p 时去重。±2% 容差，只按字节差选点；H.265 至多10次，AV1至多8次整数 CRF 搜索。无法命中如实记录，不填字节。
4. 连续诊断预定使用 video6、video91、video24 的首250帧；若资料检查发现连续性或图像尺寸问题，先记录原因再调整。video91 沿用来源时间推断的15 fps，其余沿用25 fps。它们是旧工程已有资料，不冒充新的独立测试集；摄录独立性以实际来源资料为准。
5. 连续片段固定 GLC 540p / q0 / reset32 / GOP64，与相同工作分辨率、相近文件大小的 H.265 / AV1 比较。video6另跑GOP128以观察较长I帧间隔；同样保留其文件预算对照。540p在出结果前指定，不按质量结果挑选。
6. 指标：全帧 RGB PSNR、MS-SSIM；有发布者GT的帧才计算鱼区误差；相邻帧重建误差的变化量作为时序诊断，不能直接称为感知闪烁分数。保存逐帧曲线、I帧与reset位置。
7. 感知指标优先使用 GLC 所带 DISTS 实现，下载可信来源的 VGG16 权重并保存哈希。短片段评价全部50帧；长片段在开始前固定为每10帧、全部有鱼GT帧以及 I/reset 前后各1帧的并集，统一在720p RGB上计算。权重或推理失败时明确标记缺失，不用别的数字冒名替代。
8. 展示图包括固定源帧60/75/90全部GT目标、同一个位置跨时刻对照、预先指定的长片段首/中/末帧；不挑选有利案例。静态图不能证明时序稳定，因此另提供连续播放材料。任何人工评分均留空，等待用户真实查看。
9. 20–40 kbps仅表示链路发送速率；本轮等待时间按真实完整文件负载估计，不是新网络实传，也不是编码视频平均码率限制。模型、原图、码流和逐帧输出留本地，只上传脚本、报告、小型证据和精选展示图。

## 关键帧审计修正（感知指标计算前）

初版普通编码命令共用了 `-force_key_frames expr:gte(n,n_forced*64)`。ffprobe 检查发现本机 FFmpeg / libaom 组合使短片 AV1 的关键帧落在索引0和1，而不是只有0。同一CRF的最小复现实验去掉强制表达式、改用 `-g 64 -keyint_min 64` 后恢复只有索引0，完整文件从45,614 B降至42,923 B。该检查仅用于修复时序配置，不按画质选优。

因此在正式指标计算前，归档全部5个初版AV1短片目录，按修正参数重新执行同一有界预算搜索；H.265与GLC不变。长片AV1从第一次运行就使用修正参数。所有普通编码最终结果强制验证实际帧数及关键帧位置，必须等于 `0, GOP, 2*GOP, ...` 才进入结果表。审计原始记录与旧文件保存在本地 `av1_keyframe_audit` 和 `corrections/av1_forced_keyframe_pre_fix`，最终报告明确说明修正。
