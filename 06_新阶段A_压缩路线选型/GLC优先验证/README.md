## 2. 为什么需要补这一轮

[GLC 论文](https://arxiv.org/abs/2505.16177)及[作者仓库](https://github.com/jzyustc/GLC)强调低码率下的感知质量。前轮没有 DISTS、盲评或连续播放的时序评价，不能只凭 PSNR 排名排除 GLC。

前轮的 q0 / 720p / GOP32 配置产生 43,623 B 的 2 秒文件；这是该配置的测量点，**不是所有 GLC 配置的最低文件大小**。更低预算是否能达到、是否保住小目标，都必须实测。q0 已是本地已用质量范围的低端，不能通过越界 q 值、截断码流或修改质量标签声称得到了合法低码率点。

20–40 kbps 继续只限制链路发送速率。低文件预算是为了测画质与等待时间的取舍，没有变成用户新增的文件上限或实时要求。

## 3. 第二轮验证设计与验收依据（历史保留）

以下保留第二轮的设计与原验收口径，便于复现和区分已经完成的开发诊断与尚未完成的正式评审；不是2026-10-18之后要重新执行的一套参数搜索。

### A-G1：先找可达的更低预算

用同一段 50 帧、25 fps、2 秒的开发片段做有界探索，先检查现有真实码流接口是否支持候选参数。源帧与显示时长固定，所有方法评价同一输入。

| 步骤 | 候选配置 | 要回答的问题 |
|---|---|---|
| 固定 720p，改变 I 帧间隔 | GLC q0，GOP32 / 64 / 128，先固定 reset32 | 减少 I 帧开销能否降低完整文件大小，代价是什么？50 帧时 GOP64/128 都只有首 I 帧，等价配置不重复跑 |
| 固定时序设置，降低工作分辨率 | 720p / 540p / 360p，保持相同源帧和显示帧率，统一还原至 720p 评价 | 更低预算是否只能靠降低空间分辨率实现，小鱼是否因此消失？ |
| 普通编码器对照 | H.265 / AV1，完整文件大小匹配；保留原分辨率和相同降采样条件两类对照 | 观察到的收益来自编码器，还是输入分辨率改变？ |

2 秒开发片段的建议探索档为 **10 / 20 / 30 / 40 KB**，其中 1 KB = 1,000 B。这是试验预算，不是产品要求。对应视频文件平均码率为 40 / 80 / 120 / 160 kbps；20 kbps 链路的纯文件等待时间为 4 / 8 / 12 / 16 秒，40 kbps 时减半，均不含协议开销和处理时间。

先记录 GLC 配置真实能达到的文件大小，再按这些字节数匹配普通编码器，不假定可以精确命中每个建议档。候选只按字节差选点；容差仍为 ±2%，无法命中就报最近点及差值。所有容器、必要元数据和应用载荷计入完整文件；预共享模型成本另列。未达到目标预算记为“不可达”，不填充字节，不静默改帧数。

### A-G2：观感和目标保真一起看

- **观感**：准备匿名、随机顺序的正常速度播放对照；先看无框完整视频，再看目标局部。原图、GLC、H.265、AV1 使用相同播放条件；展示预览的额外压缩必须可控，指标直接从解码像素计算。
- **感知指标**：已复用官方 DISTS 实现与可信来源权重，保存版本和哈希，完成第二轮预定评价。PSNR / MS-SSIM继续作为辅助，不能替代观感与语义判断；正式人工盲评仍待真实评审输入。
- **目标保真**：分别记录鱼/潜水员的可见性、数量、轮廓、位置和动作，有无消失、凭空出现或明显形变。先保存原图判断，再评价重建，原图无法判断的目标单列。
- 发布者 GT 与新增人工核对分开，未标注帧不等于无目标。现有分割器结果只作辅助，不能将模型漏检直接判成编码失败，也不能将较高鱼区 PSNR写成识别率提升。
- 评分项目和通过口径在揭晓方法身份前固定。人工意见需要真实评审输入，脚本输出和助手看图都不计作用户评分。

### A-G3：连续片段检验时序稳定性

2 秒片段只能筛选配置，不能验收长时序。随后冻结至少三个来源独立的连续水下片段清单，单段尽量达到 10 秒 / 250 帧或更长，覆盖小鱼、潜水员、相机运动和弱光。若素材不足，先补素材；video6 的不同片段不能当成独立场景。

沿用 A-G1 选出的少量配置，记录每帧质量、目标可见性、I 帧及参考重置位置，重点检查闪烁、纹理跳变、目标忽隐忽现、动作或形状突变，以及随时间累积的退化。GOP64 / 128 的差异必须在足够长的连续片段上比较，不能从 50 帧的相同首 I 帧设置推断。

诊断可记录重建与原图的相邻帧差分误差、逐帧质量曲线；这些量会受真实运动影响，**不能直接当作感知闪烁分数**。正常播放与慢放核对分别记录，最终判断仍须对照原始运动。若修改参考重置间隔，应与 GOP 变化拆开，避免同时改多项参数后无法归因。

长片段比较先固定完整时长，再匹配完整文件大小，同时报告 B/秒和 20 / 30 / 40 kbps 下的等待时间。不将更短片段的小文件视作压缩更好。

## 4. 采用 GLC 的依据

本阶段按以下顺序决策，具体数值阈值在正式评审前固定：

1. **能可靠恢复**：真实完整码流独立解码，编码端与解码端校验一致；不能依赖读取源视频。跨设备能力另行测试，未测不能宣称。
2. **目标内容可信**：不以生成得更自然为由忽略目标消失、伪目标、数量变化或明显动作失真；发现问题就明确其适用预算和场景边界。
3. **时序可用**：连续片段没有影响观看和目标判断的明显闪烁或累计退化，重置附近异常也须报告。
4. **观感或传输代价有实际收益**：在相近完整文件预算下有稳定的观看偏好，或达到同等可接受质量时文件更小；不要求必须赢得所有 PSNR 指标。

如果证据支持，GLC 就作为主线推进。若只在特定预算和场景有优势，可限定这些条件采用；若目标失真是关键障碍，先调整预算、时序或分辨率并保留负结果，再判断是否需要目标增强。不能为了让 GLC 获胜而选择性忽略 H.265 / AV1 对照。
