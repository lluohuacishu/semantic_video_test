# video1 持续结构：10 秒过渡与实际辅助文件

**后续整帧迁移：** [三素材整帧实验](整帧与跨素材结构稳定实验_20261110.md)已完成。F 的 video2/3 边界明显减轻，但 video1 同框粗尺度 MAE 为 3.192，仍不如本报告 U 的 1.426；U 继续保留为已认可局部基线，不能由整帧 F 覆盖。

2026-11-10。本轮从用户已认可的 23 帧 C2 延长到固定前 150 帧、10 秒。离线过渡版 **T** 获得“整体明显更稳，过渡可接受”的原速反馈。随后把运动、可靠区和前景保护完整封装为文件，实际接收版 **U** 获得明确澄清：“**U 与之前的 T 差不多，都比原始 GLC 稳**”。这是单名用户对一个开发片段的反馈，不是盲测或完整长片验收。

U 是当前继续实验的候选基线。它复用 GLC 已有的完整 RGB 结构，沿运动持续投影，并在更换参考时做短过渡。它改善了跨帧稳定性，但没有恢复原片的真实珊瑚形状。

## 从短段到 10 秒

基础输入仍为 video1 的 512×288、15 FPS、q0、GOP64/reset32、FP32。原始 `base.glcsnd` 为 31,963 B，150 帧，完整 10 秒计费。所有评分读取无损 uint8 RGB；查看视频保持原速，没有重复帧。固定黄珊瑚框仍是 `[342,10,502,105)`，所有方法共享源画面的相邻帧 Farnebäck 对应和可靠掩码；它与渲染用的锚点 RAFT 分开。跟踪整块珊瑚的评分另存，不能混用两个区域的数值。

| 方法 | 处理 | 10 秒粗尺度时序 MAE ↓ | 细纹跨帧 NCC ↑ |
| --- | --- | ---: | ---: |
| 原始 GLC | 原始独立解码 | 4.558 | 0.434 |
| 旧 S | 每 15 帧刷新，增加结构频带 | 3.301 | 0.600 |
| M | 跨锚点继承原始 RGB 的坐标和来源 ID | 2.855 | 0.745 |
| F | 全段直接对齐第 0 帧，只有一个 RGB 参考 | 3.704 | 0.617 |
| N2 | 整块参考，每次换锚直接切换 | 1.460 | 0.914 |
| T | N2 加 6 帧、运动对齐的换锚过渡，离线稠密辅助 | **1.391** | **0.932** |
| **U** | 独立接收的实际辅助文件，17×9 网格、1/4 像素量化 | **1.426** | **0.930** |

M 只继承坐标、每帧采样原始参考 RGB 一次，避免了递归图像插值，但参考逐渐失效，覆盖碎裂。F 则为所有帧重新计算到第 0 帧的直接 RAFT；后 2 秒几乎回退到原始 GLC，说明即使没有坐标累积，单张旧参考也不能覆盖持续视角变化。两者均保留为负结果，不作为下一轮主方案。

N2 的锚点为零基 `0、15、45、75、105、135`。每个锚点的整块可见珊瑚范围由源图确定，可靠区沿用源 sigma3 颜色差 <16、双向光流误差 <1.5 像素、3×3 腐蚀和 2 像素向内羽化；源橙鱼启发式用于保护前景。**N2 的 105–127 帧逐位复现已获认可的 C2**。但五次参考刷新产生新的硬切换尖峰，因此不能只报告整段均值。

## 换锚过渡 T

在 1、3、5、7、9 秒换锚时，旧、新参考都按当前运动投影，仅在共同可靠区域内混合。旧参考权重依次为 `1、5/6、4/6、3/6、2/6、1/6`，共 6 帧、0.4 秒；第 7 帧完全进入新参考。两侧均采样各自未经处理的原始 GLC RGB，不递归采样上一显示帧。当前锚点到旧锚点的桥接运动由源 RAFT 计算。其余 120 帧逐位保持 N2。

| 固定框检查项 | 原始 GLC | N2 硬切换 | T | U |
| --- | ---: | ---: | ---: | ---: |
| 五次换锚帧粗尺度 MAE | 3.996 | 10.992 | 1.627 | 1.687 |
| 两次 I 帧（64、128）粗尺度 MAE | 12.832 | 1.712 | 1.712 | 1.736 |
| 6 秒后普通 P 对，剔除换锚帧（53 对） | 5.947 | 1.581 | 1.801 | 1.809 |

最后一行的 T/U 包含过渡内部的普通 P 帧，所以其均值略高于 N2；不能把消除换锚尖峰说成每个局部指标都更好。

五个过渡窗口连同退出帧，共 35 个帧对：N2 最大粗尺度 MAE 为 **13.566**，T 为 **2.898**。相同窗口细纹幅度从 N2 的 9.064 降至 T 的 7.789，原片为 8.111。这里确实有短暂变软的代价。用户原速反馈为“整体明显更稳，过渡可接受”；不将单项误差下降百分比写成人眼晃动改善百分比。

## 实际辅助文件 U

发送端可读取源 RGB，利用既有运动、可靠性与手工源图范围生成辅助数据。接收端的重建内容只来自独立解码的 GLC RGB 和辅助文件，**不发送源 RGB 锚帧**。原始 GLC 的熵解码、潜变量参考链和基础码流均不修改。

本轮测试两个开发配置，均使用相同 1 像素轮廓近似：

| 配置 | 运动网格 / 精度 | 完整辅助字节 | 辅助 kbps | 粗尺度 MAE | 细纹 NCC |
| --- | --- | ---: | ---: | ---: | ---: |
| **g17q4 / U** | **17×9 / 1/4 像素** | **42,793** | **34.2344** | **1.426** | **0.930** |
| g23q2 | 23×12 / 1/2 像素 | 45,681 | 36.5448 | 1.539 | 0.916 |

选择 g17q4 是本开发段上的选择，尚无独立留出评价。两配置同时改变网格与量化精度，不能据此单独归因某一个因素。

U 的传输裁剪范围为 `[240,0,512,144)`。运动在可靠珊瑚内做加权面积采样，未使用的网格点用拟合仿射场填充。文件内包含以下所有必要辅助信息：

| 辅助文件部分 | 压缩后字节 |
| --- | ---: |
| 150 帧到当前锚点的运动网格 | 12,796 |
| 30 个过渡帧到旧锚点的运动网格 | 3,220 |
| 150 个当前可靠区和 30 个过渡共同可靠区轮廓 | 23,504 |
| 150 帧小橙鱼保护掩码，逐位无损 | 2,516 |
| 格式头、基础流 SHA-256、尺寸、时间轴、锚点、过渡权重、段描述与 CRC | 757 |
| **完整辅助文件** | **42,793** |

接收端恢复轮廓与 2 像素向内羽化，展开运动，并按文件中的前景掩码检查当前与参考位置。没有额外读取未封装的多边形、鱼掩码或源光流。鱼保护仅保证启发式检测出的像素保持原始 GLC，不能据此声称所有鱼都已正确分割。

基础文件为 **31,963 B / 25.5704 kbps**，辅助文件为 **42,793 B / 34.2344 kbps**；两路分别低于 **40 kbps**。合计 **74,756 B / 59.8048 kbps**。以上使用完整文件和原 10 秒时长，不裁掉首帧、同步头或失败帧来降低账面码率。

本轮尚未做同总字节 GLC/H.265 对照，所以只能说在既定双流上限内保留了改善，不能宣称码率效率优于同总码率的普通编码。当前使用整段 LZMA 文件压缩，流式分包延迟和丢包恢复也未验证。

## 保真、原速反馈和独立核验

同一固定框，全段细纹幅度为原始 GLC 9.272、T 8.881、U 8.888。U 没有比 T 再明显降低这一幅度，但这不替代人眼清晰度检查。区域 PSNR 为原始 **16.582 dB**、T **16.450 dB**、U **16.444 dB**；源结构误差也未改善。该方法使已有的生成结构稳定下来，不能把它解释成恢复真实细节。

用户反馈按原话保存：

1. T：“整体明显更稳，过渡可接受”。
2. U 初次：“两者差不多粗略来看”。该句比较对象不清，未直接记为通过。
3. 询问比较对象，并另展示 T/U 直接对照后，明确为：“U 与之前的 T 差不多，都比原始 GLC 稳”。

已完成的核验包括：

- 原始源数组、基础流、S 和稠密运动文件哈希保持一致；所有保存数组回读检查 dtype、形状和哈希。
- 新进程重新从 31,963 B 基础文件解码，全部潜变量参考摘要通过，RGB 与冻结基线逐位一致。
- 两个实际辅助文件量化网格和无损鱼掩码往返一致；错误基础绑定、CRC 损坏、截断和超预算文件被拒绝。
- 初次接收过程与发送端模拟重建逐位一致。另用 `receive_video1_structure.py` 重放 U；它只允许读取基础文件、辅助文件，以及本地独立解码生成的 RGB 和收据。连发送端 `send.json` 都被显式拒绝，重建仍与原 U 逐位一致。
- T 与 U 的零权重区、已保护鱼像素保持原始 RGB；T 的 30 帧公式独立重建逐位一致，其他 120 帧保持 N2。
- 长段 6 个、辅助版 3 个预览独立解码，核对 150 帧、15 FPS，以及首、中、末帧每个面板与其无损来源的对应。

GLC 基础解码此次核心耗时 37.626 秒，约 3.99 FPS；U 的 CPU 显示后处理约 1.35 秒 / 150 帧，不含基础解码、源 RAFT、封装、磁盘、评分与预览。不能据显示后处理耗时宣称端到端实时。

## 文件与复现

观看入口：工作区 `05_成果与观看/GLC_珊瑚持续结构10秒_20261110/README.md`。01 为原始 GLC/U 珊瑚原速左右对照，02 为全画面，03 为 T/U。`传输文件` 下只有基础流和 U 辅助流两份实际发送文件；校验与说明在其外部。

完整运行目录：

- `02_实验数据/优化_GLC后处理/video1_persistent_long_20261110_01`：M、F、N2、T、桥接与单锚点源 RAFT、无损 RGB、逐帧评分及核验。
- `02_实验数据/优化_GLC后处理/video1_persistent_aux_20261110_01`：两种辅助文件、独立基础解码、两个接收输出、U 的纯接收重放、评分、预览及核验。
- [短段 C/C2 和 E/G 旁路](video1持续结构参考实验_20261110.md)保留为前一阶段证据。

使用已有 GLC Python 环境；以下 `$long`、`$aux` 指新的运行目录，`$upstream` 是既有 Deflicker 上游目录（含指定 RAFT 权重），`$assets` 是现有 GLC 角色资产，`$ffmpeg` 是现有 FFmpeg。每个输出子目录必须尚不存在；默认 workspace 指本工程的工作区。

```powershell
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_persistent_long.py' bridges --output $long --upstream $upstream
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_persistent_long.py' render --output $long --ffmpeg $ffmpeg
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_single_origin.py' flow --output $long --upstream $upstream
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_single_origin.py' render --output $long --ffmpeg $ffmpeg
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_reference_transition.py' --run $long --ffmpeg $ffmpeg
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_auxiliary.py' prepare --long-run $long --output $aux
python -B -X utf8 '17_优化阶段_解码器推理加速/decoder_worker.py' --stream "$aux/base.glcsnd" --output "$aux/base_receive" --backend eager --assets $assets

python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_auxiliary.py' receive --output $aux --profile g23q2
python -B -X utf8 '21_优化阶段_GLC解码后处理/run_video1_auxiliary.py' evaluate --long-run $long --output $aux --ffmpeg $ffmpeg
python -B -X utf8 '21_优化阶段_GLC解码后处理/receive_video1_structure.py' --base "$aux/base.glcsnd" --decoded "$aux/base_receive" --auxiliary "$aux/g17q4/structure.glcstruct" --output "$aux/g17q4/standalone_receive"
python -B -X utf8 '21_优化阶段_GLC解码后处理/verify_video1_persistent_long.py' --long-run $long --aux-run $aux --ffmpeg $ffmpeg
```
