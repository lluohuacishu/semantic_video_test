# D 轮：文件增幅不超过 10% 的语义引导视频编码

**D2 大目标低码率修订已完成（2026-10-22）：** 按用户要求换为 011/021，保留原帧率，采用 512×288。完整发送文件必须同时 ≤40 kbps、且相对冻结普通 GLC 基准增幅 ≤10%；六个独立解码输出均达标，实际 32.91–39.85 kbps。011 全部触发保护过大回退，021 鱼区 PSNR 相比普通 GLC 为 −0.082 dB，语义收益仍未成立。当前没有 D2 GPU 任务。 见 [新报告](D2大目标低码率结果_20261022.md)和[当前协议 v3](d_round_protocol_v3.json)。下方 1080p 和 D1 记录为历史；旧 300 多 kbps 不属于可接受应用结果，旧“30–40 kbps 仅供参考”已被覆盖。

日期：2026-10-21。状态：**D1 首轮及 2×2 权重/输入对照完成，定位覆盖改善但门槛仍未通过，D2 尚未开始。** SUIM 底模 + 原尺寸分块成为当前诊断组合，三段鱼保护覆盖为 78.22% / 98.89% / 91.54%，378/454 实例×帧达到九成覆盖、27 个完全无交集。潜水员联合保护平均 89.23%、16/20 图达九成，仍有缺口。正式收发默认配置未改。当前目标仍是每段完整文件相对普通 GLC 最多增加 10%，让鱼和潜水员更清楚。

**D1 评审更新：** 已用缓存拆分鱼/潜水员贡献。潜水员分支对三段已标鱼覆盖只多贡献 0.54 / 0.19 / 0.00 个百分点，却占联合保护面积的 33.93% / 19.78% / 13.59%。下一步优先验证 GT/预测保护能否改善 GLC 重建，再决定是否训练；256 原尺寸滑窗最多补一组，不作为新门槛。见 [评审与后续顺序](D1外部评审与后续顺序_20261021.md)。本次仅 CPU 缓存计算，新推理和 D2 未运行。

主线：限制每段文件增幅，编码时优先保护目标。先做发送端语义保护/背景简化与现有 GLC 的预算匹配，必要时再做语义率失真适配或空间控制。原解码后增强是可选辅助，不是前置条件；核心验收为真实目标保真、时序稳定和背景代价。

**当前预算：** 基准 S0 为同片 A@q32 完整发送字节，硬上限为 floor(11×S0/10)，包含必要侧信息；各组都有相同预算机会。无增量和 ≤10% 增量分列，2% 仅作严格近等体积配对标签。原 20 kbps 是链路速率假设，旧 10 秒/40,000 B 预算折算为 32 kbps 文件码率。30–40 kbps 为可接受参考，仍须遵守逐片 10% 上限；实际码率与发送时间另报。
